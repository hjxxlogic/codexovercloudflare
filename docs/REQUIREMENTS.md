> 状态：需求基线与 C++ 架构修订。版本：0.2。日期：2026-10-24。
> 来源：[原始构想](IDEARS.md)。技术实现见 [技术架构](ARCHITECTURE.md)。

## 1. 项目背景与目标

远程服务器没有公网 IP，但可以访问互联网，且已经安装并完成 Codex 登录。用户希望在其他电脑上操作该服务器上的 Codex，不需要开放入站端口或配置公网 SSH。

项目提供三部分：服务器上的管理程序（Agent）、客户电脑上的 CLI 入口和网页界面，以及部署在 Cloudflare 上的实时中继。模型调用、命令执行、文件修改、Codex 凭据与项目文件均留在远程服务器。

成功标准：用户在外部网络中能够选择远程项目，通过 CLI 或网页完成“提出任务—查看输出—审批操作—查看结果”，连接中断不导致任务被重复执行。

## 2. 用户、环境与边界

### 2.1 目标用户

首版面向个人开发者：一个所有者、多台受其信任的服务器和客户端。每台服务器允许多个独立会话，但一个会话同时只有一个控制端。操作者具有执行远程代码的权限，不能将服务开放给不受信任的访客。

### 2.2 首版支持范围

- 本机实现：`coc-agent` 与 `coc-client` 必须采用 C++17，独立二进制运行不依赖 Node.js；中转与网页继续使用 TypeScript。项目配置与 SQLite 格式保持兼容，0.3.0 认证升级需重新授权。
- 统一设备登录：A / CC / CW 向 R 发起 5 分钟有效的登录请求，在管理网页核对角色、设备名称、目标 A 与配对码后批准。设备凭证无固定有效期，直到 R 撤销。A 只提供自身服务端功能，CC / CW 凭证只能访问绑定的一个 A，互相不能替代；客户端没有管理权限。
- API_KEY：管理网页生成时限定 coc-agent / coc-client；CC Key 创建时绑定目标 A，A Key 首次使用绑定自己的 A，绑定不可修改。Key 本身直接访问，不兑换其他长期凭证；持有即可使用，直到 R 撤销，与配对审批并行。完整 Key 仅生成时显示一次；撤销即时关闭连接，A 撤销级联客户端。
- 多授权与管理：CC 本地文件和 CW 持久化 HttpOnly Cookie 保存多个 A 的独立凭证，支持切换；本地清除不撤销 R 授权。管理身份独立，仅能审批 / 拒绝 / 撤销；撤销关闭相应已有连接，撤销 A 同时使其全部客户端授权失效。
- 服务端：Linux x86_64；通过 systemd 常驻运行；其他架构后续按测试结果支持。
- CLI：当前 C++ 版本验证 Linux x86_64；macOS、Windows 原生 CLI 列为后续兼容项。
- 网页：桌面 Chromium、Firefox；移动端可进行基本会话操作。
- 网络：服务端和客户端能够向 Cloudflare 发起 HTTPS/WSS，服务端能够访问其配置的模型服务。
- Codex：优先验证本机已检查的 `0.164.0`；发布时锁定经过端到端测试的确切版本，不承诺任意版本兼容。

### 2.3 非目标

首版不提供多租户 SaaS、计费、多人共同编辑、通用 SSH/桌面远控、任意 TCP 转发、完整文件管理器、文件上传下载、语音/图片输入或跨主机迁移正在运行的任务。不会自动同步客户端文件或替用户解决 Git 冲突。

## 3. 核心使用流程

1. 所有者部署 Cloudflare Worker 和 Durable Objects，配置访问凭据。
2. 在服务器上安装 Agent，配置中继地址、设备凭据及允许使用的项目根目录。
3. Agent 主动连接中继；客户端登录后看到主机状态和项目列表。
4. 用户选择项目，创建会话；Agent 在服务器上启动对应 Codex runtime。
5. CLI 启动原生 Codex TUI；网页显示结构化对话、工具活动和审批。
6. 用户提交任务并实时接收输出；需要审批时明确选择允许或拒绝。
7. 客户端短暂离线后重新连接；网页补齐事件，CLI 尝试重新附着或恢复线程，并明确展示恢复结果。
8. 用户主动停止本轮任务或结束会话；结束会话不删除代码和 Codex 历史。

| F-05 | P0     | CLI 入口使用远程服务器的 Codex、工作目录和模型配置，支持多轮对话、流式输出、审批和中断。          |
| F-06 | P0     | 网页支持登录、主机/项目选择、会话列表、文本输入、流式答复、工具状态、代码差异及错误展示。         |
| F-07 | P0     | 命令、文件变更及用户输入等交互请求往返转发；显示远程上下文、请求内容和处理结果，绝不自动同意。    |

| F-12 | P0     | 访问鉴权、过期、撤销、Origin 校验、项目权限校验与限流覆盖 HTTP 和 WebSocket。                     |
| F-13 | P0     | 提供健康检查、脱敏日志和运行指标；可区分模型错误、Codex 退出、主机离线与中继断线。                |
| F-14 | P0     | 管理程序启动时验证 Codex 版本、项目路径及协议能力；不兼容时拒绝启动新会话并说明原因。             |
| F-15 | P1     | 会话搜索、归档、只读观察端、更多操作系统、附件和历史清理界面。                                    |
| F-16 | P1     | 同一逻辑会话在 CLI/网页间切换；首版仅承诺同模式恢复，跨模式不能假设协议状态通用。                 |

### 4.1 CLI 交互约定

本地只提供 `coc-agent` / `coc-client`，尽量共用代码并保持基础接口一致：

```bash
coc-agent login --relay https://relay.example.com --project /srv/project
coc-agent run
coc-client login --relay https://relay.example.com --host A_ID
coc-client hosts
coc-client projects --host build-server
coc-client connect --host build-server --project my-project
coc-client sessions
coc-client attach <session-id>
coc-client stop <session-id>
```

`connect` 创建会话并启动本地原生 Codex TUI。所有路径提示必须标注为远程路径。本地附件、剪贴板图片、外部编辑器等依赖本机文件的能力首版不支持，必须给出明确提示。

### 4.2 网页交互约定

页面至少包含登录入口、主机/项目选择、会话列表和会话详情。详情页展示连接状态、任务状态、消息流、审批区及停止按钮；文本中的 HTML 必须净化，工具输出默认视为不可信文本。

断线时禁用新任务提交并显示重连状态；恢复时先同步当前轮次和未决审批。审批按钮提交后等待确认，重复点击不得产生重复决策。首次加载只请求最近记录，历史记录分页读取。

## 5. 状态与恢复要求

连接状态和任务状态分别记录，不能因客户端断开将任务标记为失败。

- 主机：`offline → connecting → online`；被撤销时为 `disabled`。
- 会话：`starting → ready → closing → closed`；异常退出为 `failed`。
- 轮次：`idle → running ↔ waiting_approval → completed / interrupted / failed`。
- 客户端：`attached / reconnecting / detached`。

客户端断开后 runtime 默认保留 30 分钟；到期先请求中断，再关闭进程，记录原因。未决审批默认等待最多 10 分钟，到期拒绝并记录，适配器无法安全拒绝时终止该会话。Agent 重启后的历史恢复必须显式展示，不能假装进程从未中断。

## 6. 非功能要求与初始容量

以下是受控环境验收目标，不是 Cloudflare 或模型服务的 SLA。

| 类别     | 初始目标及测量方式                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------- |
| 容量     | 单所有者 5 台主机；每主机最多 4 个 runtime；每会话 1 个控制端。超限明确拒绝。                      |
| 延迟     | 网络 RTT ≤ 100 ms、单主机 4 会话时，事件进入 Agent 至客户端收到的 P95 ≤ 300 ms；排除模型生成耗时。 |
| 重连     | 网络恢复后 P95 15 秒内重新建立连接；不包含客户端完全休眠和人工重新登录。                           |
| 流量     | 单协议消息最大 256 KiB；单逻辑事件最多 8 MiB，分片传送；超限明确报错或截断并标记。                 |
| 背压     | 每会话待发送队列最多 8 MiB；慢端不能无限占用内存，溢出后断开并要求重同步。                         |
| 稳定性   | 4 会话持续运行 8 小时，无重复执行、跨会话串流或无界队列增长。                                      |
| 数据保留 | 网页事件日志默认保留 7 天、每主机合计最多 1 GiB；触达上限清理最旧已结束会话并报告回放缺口。        |
| 可维护性 | 协议版本明确；配置有示例；提供服务启动、升级、回滚、备份和故障排查说明。                           |

## 7. 安全与数据要求

- Codex 登录凭据只保存在服务器，Agent 与用户访问凭据分开管理；CLI 凭据使用系统凭据库或权限为 `0600` 的配置文件。
- 使用 TLS；首版信任 Cloudflare 中继，**不提供端到端加密**。代码片段、命令和对话会经过中继，必须在部署说明中说明。
- 云端默认不持久化对话、代码或命令输出；远程服务器存储 Codex 历史和网页回放日志。关闭会话不等于删除这些数据。
- 访问范围至少绑定所有者、主机、项目和会话；用户输入的 ID 不是授权凭据。
- 不默认关闭 Codex 审批与沙箱；服务端固定权限上限，客户端不能通过启动参数或 RPC 提升权限。
- 首版的项目白名单是入口约束，不能被宣称为强租户隔离；强隔离需另用容器/独立系统用户。
- 日志不记录令牌和消息正文；记录连接、授权、审批结果、异常和主动接管的元数据。

## 8. 验收场景

| 编号 | 场景             | 通过标准                                                                              |
| ---- | ---------------- | ------------------------------------------------------------------------------------- |
| A-01 | 无公网 IP 服务器 | 仅开放出站网络，CLI 与网页分别完成创建文件、读取差异和多轮追问。                      |
| A-02 | CLI 原生体验     | 在固定 Codex 版本验证初始化、历史读取、流式输出、审批、中断及终端尺寸变化。           |
| A-03 | 审批闭环         | 允许、拒绝、超时、重复答复及重连后答复均有确定结果，无隐式同意。                      |
| A-04 | 中断与重连       | 客户端/Agent 链路分别断开 60 秒，任务不重发；网页补齐保留事件，CLI 显示准确恢复状态。 |
| A-05 | 进程异常         | 杀死 Codex 或重启 Agent 后显示失败/恢复状态；不重新执行状态不明的任务。               |
| A-06 | 隔离与鉴权       | 非法令牌、过期票据、越权会话、非白名单路径和旧控制端操作全部被拒绝。                  |
| A-07 | 中继重建         | Durable Object 休眠唤醒和部署断连后可恢复路由，不将消息投递到错误会话。               |
| A-08 | 压力与慢端       | 按第 6 节容量及 8 小时测试验证延迟、队列限制和大消息拒绝/分片。                       |
| A-09 | 撤销与接管       | 撤销在 60 秒内终止对应存量访问；接管后旧端不能提交或审批。                            |

## 9. 交付阶段

1. **M0 技术验证**：原生 `codex --remote` 经双向中继运行；核实最小 RPC 集、审批、DO 休眠及重连。输出兼容性报告；不通过前不冻结 CLI 实现。
2. **M1 核心链路**：设备注册、鉴权、项目配置、Agent 常驻、会话生命周期及 CLI；完成 A-01 的 CLI 部分、A-02、A-03、A-06。
3. **M2 网页与恢复**：网页交互、事件日志、恢复、控制权及异常处理；完成其余功能场景。
4. **M3 可发布版本**：容量测试、安全测试、安装与运维文档、版本兼容表、升级回滚演练，完成全部 P0 验收。

## 10. 默认假设与后续决策

按“个人自托管、可接受 Cloudflare 接触明文、Linux 服务端、无需文件同步”推进设计。部署域名、实际机器数量、模型供应商和预算由部署配置提供，不阻塞本需求基线。若需要不可信多用户或中继不可见内容，必须重新设计身份、进程隔离和加密层。
