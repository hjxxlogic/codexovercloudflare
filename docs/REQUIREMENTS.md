# 项目需求文档

## 运行版本展示

管理页面须显示各服务器正在运行的 coc-agent 版本，使用当前 Agent 连接上报信息，不能替换成下载清单版本；离线、状态查询失败及旧 Agent 未上报版本应区分。功能菜单在 CW / 管理员模式及登录前均须显示当前网页构建的版本号，无需新增周期查询。

## 可靠会话通信（0.5.18）

Worker 持久保存双方发送头并在每次会话业务命令中携带；A / CW / CC 保存连续接收位置，发现缺口补取。会话副作用命令在发送前落盘，接收方按条数 / 字节发放信用，未完成命令占用执行缓冲；审批 / 中断不能被普通命令耗尽的窗口阻塞。纯读取使用原协议，由请求端重试。重复命令不重复执行，结果未确认时查询原身份；进程重启与存储回退不得触发未知副作用自动重放。旧协议兼容与完整保证的边界须明确说明。

## CW 首次连接与刷新恢复

运行期间普通请求失败不得清空登录、会话或草稿；认证撤销与服务可用性失败须使用不同 HTTP / WebSocket 错误语义，后端未知错误不得伪造成 INVALID_REQUEST 或认证失效。

首次工作区初始化失败不得永久阻止项目 / 会话加载；临时故障有限重试，显式刷新可恢复。通知与历史订阅必须在有界时间内确认，连接超时恢复不得依赖关闭事件送达；本地缓存阻塞不能无限阻止网络初始化。Relay 应忽略关闭中的旧控制端，同时保留有效控制端的显式接管规则。正常空闲无新增周期请求。

## CW 底部自动刷新

CW 用户向下翻页到达消息底部，或已在底部继续向下滚动时，自动同步当前会话和消息；支持桌面与手机，保留草稿和当前控制连接。连续手势去重，避免自动跟随消息引发循环刷新；向上查看历史、工具内部滚动及空闲时不额外刷新。

## Agent 邮箱关联与更新通知

- 管理员可以在网页中向全部有效 Agent 提交当前已部署版本的更新通知，显示处理中、成功和失败状态；不强制开启自动更新或中断会话。
- 每个 Agent 支持多个关联邮箱，既可由管理员网页配置，也可由本地 `accessEmails` 或 `access-emails` 命令配置。管理员覆盖优先，并能清空或恢复 Agent 默认值。
- 服务端验证该邮箱后，所有 CW 浏览器自动获得对应主机访问权，不需要再次配对；不能扩大到其他主机、CC 或管理权限。无邮箱身份和访客不适用。
- 关联删除使仅由关联产生的凭据失效并关闭连接，独立配对授权保留；显式撤销不能因 Agent 重连而自动恢复。默认不关联邮箱，无固定数量配额，旧配置兼容。

## CW 文件预览、工具同步与 Agent 自动批准

聊天链接和工作区文件中的 Markdown / 文本文件单击后在新窗口打开；顶部“下载”保存完整原文件。Markdown 支持表格和代码块，HTML、代码等其他文本按纯文本显示。图片、音频、视频单击在页面内展开，媒体使用浏览器播放控件；再次单击收起，不支持的格式可下载。预览沿用项目授权、路径限制和版本固定的分块读取；文件内容不会作为 HTML 脚本执行。

“自动批准当前会话”由新版 coc-agent 保存和执行，网页关闭或重连后继续有效。只处理当前 web 会话的命令、文件修改和本轮额外权限；其他交互仍需人工处理，不更改 sandbox 或原客户端策略。关闭开关阻止之后的自动批准，已提交决定不撤回；停止会话后关闭，其他会话默认关闭。启用时该会话不因网页离开满 30 分钟而自动停止。旧 Agent 不提供此开关能力，须升级 Agent。

Agent / CW / CC 使用已接收修订游标及最大修订号同步。条目 seq 可以保持不变，revision 随工具状态和输出更新递增；连续传输直接推进游标，前序修订不匹配时补读缺失范围。缓存提交游标前先保存对应事件；展开的工具输出在修订变化后按需重读，避免依赖顶部刷新。查看较早历史时仍更新已显示工具的状态。

## D1 与在线 DO 分离 · 2026-10-29

- 活动会话的控制版本、租约、操作关联和结果保存在 DO 原生持久存储；D1 保存不活动主机的完整快照及共享授权 / 目录元数据。
- 全部连接和在途工作结束、持续空闲 60 秒后才分批归档。新活动取消未发布归档；完整保存后切换权威位置并清理 DO。恢复完成前不得处理会话或重置 epoch。
- 复制 / 恢复可续传，失败保留源数据；离线确认 / 清理须与激活互斥，已删除回执不能因重连复活。活动 DO 缺失时拒绝使用旧快照。
- 保留授权隔离、及时撤销、显式接管与结果未知语义；回执恢复只查询原身份、不得重发任务。提供真实 Wrangler 归档 / 再激活和完整 CI 回归。详见 [D1 说明](d1-relay-state.md)。

## CW 恢复及管理易用性 · 2026-10-29

- 顶部刷新须对当前会话控制与历史通道执行实际同步，补回漏消息；通道表面打开但不响应时须有限等待并请求重连，不能仅凭主机 probe 报告会话已刷新。
- CW 菜单登出文字后须显示当前登录邮箱，切换语言时保留邮箱。
- 已授权设备支持按 Agent 或 CW/CC 折叠查看授权关系，各授权独立撤销；新增上次看到的成功认证时间，无历史记录时显示未知。名称分组不能成为授权依据，不新增空闲轮询。
- 全部管理表格须支持单击任意表头升序、再次单击切换降序，并显示方向；时间按原始时间戳比较，无记录的时间排末尾，排序不能改变撤销目标。管理会话页尚无数据表格。

## Cloudflare Access 与邮箱授权增补（2026-10-28）

- 受保护的主 Cloudflare Access 应用必须分别关联普通用户 `Allow` 策略及服务令牌 `Service Auth` 策略，不能合并为一条策略。

- 普通 Web 入口验证邮箱，访客入口仅按 CoC 授权。A / CC 和相关工具共用项目明文 Service Token，编译默认值来自同一配置；Cloudflare Access 独立负责 Service Token 准入；Worker 不依赖项目 Token 配置或 Client 字段，只使用已验证邮箱关联用户 Key，CoC API Key 继续决定原生角色及目标。A / CC 支持成对环境变量覆盖文件或内置 Client ID / Secret，但不得扩大可信 origin；缺失、空值或非法值必须拒绝。
- 一个已验证邮箱在数据库中关联全部获批 A。新浏览器完成邮箱登录后恢复授权，不重复配对；未获批邮箱不能访问其他人的 A，原生 Agent Key 不下发给网页。
- 唯一配置的管理员邮箱自动获得 owner，其他邮箱凭正确管理员密钥进入管理。自动管理、密钥管理、web 会话角色独立；邮箱或配置切换不能复用错误身份的 Cookie。
- 首次授权、迁移和撤销必须事务化；授权撤销作用于该邮箱 / A 的所有浏览器，A 撤销级联失效。未启用 Access 时旧部署行为保留。完整实现与验收见 [Access 说明](cloudflare-access-coc-auth.md)。

## 0.5.12 按需通讯验收基线

- 2026-10-28 修订：稳定 A 与 A–CW 无周期业务数据或 HTTP 查询；Agent 每 30 秒发送 WebSocket 协议 Ping，90 秒未收到匹配 Pong 关闭连接并有限退避重连。普通业务流量不替代 Pong；心跳不进入 DO 业务 handler，不周期读取授权或写入存储。Pong 仅证明传输存活，业务可达仍由 probe 确认。CW 必须有刷新、加载、最近确认、未确认 / 失败与显式唤醒重试。CC 等待 / 交互每十秒最多一轮，完成立即停止，不并发堆积。
- 所有远程控制使用可恢复关联，DO 发出消息后结束 handler，不等待 Agent；客户端超时保留结果未知语义及原 requestId。64 个在途、256 个临时回执与跨休眠 receipt 预算不能被重建绕过。
- 按活动校验发送者及接收者；五秒缓存及主动撤销保留，通知丢失不再承诺固定撤销关闭期限。订阅必须按管理员、主机授权或申请秘密独立验证。真实活动 / 刷新 / 重连补快照，无 ACK 超时重发或周期扫描。
- 永久授权不续 alarm，真实到期索引有界迁移、幂等清理，保留 epoch / lease / 权威结果和历史。平台 24 小时休眠与实际节费必须另有受控 Cloudflare 指标证据，本地测试不作替代。

## 代理、显示名与管理分组增补（2026-10-26）

- Agent / CLI 支持 HTTP、SOCKS5 代理、可选认证、私有配置持久化与单次覆盖。HTTP / WebSocket / 远程 TUI 使用一致策略；本机与私网目标绕过代理，Codex app-server 本地通道不受影响；保留 TLS 校验、超时及错误后不自动直连的约束。
- 两类原生实例具有可配置的友好显示名，可在登录前设置、登录时指定、授权后修改；名称独立于主机 ID 与凭证，不改变授权范围。网页和日常状态展示名称。
- 管理员各功能按 Tab 分组，覆盖待授权、已授权、唤醒、API Key 与管理会话；适配手机及键盘操作。
- Codex 远程地址显式携带默认端口，连接失败可附着已创建会话，无须重复创建。

## 离线唤醒增补（2026-10-25）

- 每个 Agent 可附加唤醒 URL，由管理员或持有 Agent 凭证者配置；管理员支持覆盖、禁用和恢复 Agent 配置，离线时仍可管理。
- 已授权 CW 选择离线主机、CC 访问发现离线时自动请求唤醒，只有目标主机凭证可触发；保持所有既有审批和隔离规则。
- 云端持久保存 URL，代发 GET，客户端不接收 URL 或凭证；在线不访问，按主机一分钟限流一次，失败同样限流。HTTPS 验证、请求超时和重定向禁用均由中继执行。
- 唤醒后等待真实在线状态；未配置、失败或未恢复时提示错误，不声明开机成功，不重复执行未知结果的操作。

## 1. 项目背景与目标

远程服务器没有公网 IP，但可以访问互联网，且已经安装并完成 Codex 登录。用户希望在其他电脑上操作该服务器上的 Codex，不需要开放入站端口或配置公网 SSH。

项目提供三部分：服务器上的管理程序（Agent）、客户电脑上的 CLI 入口和网页界面，以及部署在 Cloudflare 上的实时中继。模型调用、命令执行、文件修改、Codex 凭据与项目文件均留在远程服务器。

成功标准：用户在外部网络中能够选择远程项目，通过 CLI 或网页完成“提出任务—查看输出—审批操作—查看结果”，连接中断不导致任务被重复执行。

## 2. 用户、环境与边界

### 2.1 目标用户

首版面向个人开发者：一个所有者、多台受其信任的服务器和客户端。每台服务器允许多个独立会话，但一个会话同时只有一个控制端。操作者具有执行远程代码的权限，不能将服务开放给不受信任的访客。

### 2.2 首版支持范围

- 本机实现：`coc-agent` 与 `coc-client` 必须采用 C++17，独立二进制运行不依赖 Node.js；中转与网页继续使用 TypeScript。项目配置与 SQLite 格式保持兼容，0.3.0 认证升级需重新授权。
- 统一设备登录：A / CC / CW 向 R 发起 5 分钟有效的登录请求，核对角色、设备名称与配对码后批准。CC / CW 支持最多 1000 字符的选填留言；未指定目标时，管理员必须选择未停用的 A，服务端在审批事务内校验并绑定服务器。0.5.5 的指定目标申请由 CC `login --host A_ID` 或 CW 选填服务器 ID 发起；对应 Agent 可列举、明确批准或拒绝，管理员也可处理但不能改绑。Agent 运行时立即后台检查并收到指定主机变更通知后发现新申请，输出核对信息和人工审批命令，同次运行去重；网络失败不得阻塞会话或自动批准。Agent 无权处理其他 A、未指定目标或新 Agent 的申请；事务内复核审批凭证、API Key 和主机有效性，并发审批最多签发一次。新客户端遇到不支持指定目标的 Relay 必须报错。设备凭证无固定有效期，直到 R 撤销；CC / CW 只能访问绑定的一个 A，没有设备审批权限。API Key 登录继续校验创建 Key 时绑定的目标。
- 原生配对轮询在 HTTP_TIMEOUT / HTTP_NETWORK 后须在原申请有效期内恢复，不重复创建申请；批准结果可凭原轮询秘密重取，复核撤销和主机状态。已领取凭证不因临时请求到期清理而撤销，未领取结果仍到期撤销；CW 保持单次交付。
- API_KEY：管理网页生成时限定 coc-agent / coc-client；CC Key 创建时绑定目标 A，A Key 首次使用绑定自己的 A，绑定不可修改。Key 本身直接访问，不兑换其他长期凭证；持有即可使用，直到 R 撤销，与配对审批并行。完整 Key 仅生成时显示一次；撤销即时关闭连接，A 撤销级联客户端。
- 多授权与管理：CC 本地文件和 CW 持久化 HttpOnly Cookie 保存多个 A 的独立凭证，支持切换；本地清除不撤销 R 授权。管理身份独立，仅能审批 / 拒绝 / 撤销；撤销关闭相应已有连接，撤销 A 同时使其全部客户端授权失效。
- 服务端：Linux x86_64（systemd）及 Windows x64（前台或任务计划程序）；Windows 要求 Windows 10/11 或 Server 2019+，其他架构后续按测试结果支持。
- CLI：C++17 原生构建支持 Linux x86_64 和 Windows x64；macOS 列为后续兼容项。Windows 使用原生 codex.exe、Windows Terminal 及手动 ZIP 升级，实际验证边界见测试记录。
- 网页：桌面 Chromium、Firefox；移动端可进行基本会话操作。
- 网络：服务端和客户端能够向 Cloudflare 发起 HTTPS/WSS，服务端能够访问其配置的模型服务。
- Codex：优先验证本机已检查的 `0.164.0`；Agent / CLI 不强制版本号，仅检查版本命令可执行，不承诺任意版本的 app-server / TUI API 兼容。

### 2.3 非目标

首版不提供多租户 SaaS、计费、多人共同编辑、通用 SSH/桌面远控、任意 TCP 转发、完整文件管理器、自动文件同步、语音/图片输入或跨主机迁移正在运行的任务。不会自动同步客户端文件或替用户解决 Git 冲突。

## 3. 核心使用流程

1. 所有者部署 Cloudflare Worker 和 Durable Objects，配置访问凭据。
2. 在服务器上安装 Agent，配置中继地址、设备凭据及允许使用的项目根目录。
3. Agent 主动连接中继；客户端登录后看到主机状态和项目列表。
4. 用户选择项目，创建会话；Agent 在服务器上启动对应 Codex runtime。
5. CLI 启动原生 Codex TUI；网页显示结构化对话、工具活动和审批。
6. 用户提交任务并实时接收输出；默认逐项选择允许或拒绝，也可明确开启 CW 当前会话自动批准。
7. 客户端短暂离线后重新连接；网页补齐事件，CLI 尝试重新附着或恢复线程，并明确展示恢复结果。
8. 用户主动停止本轮任务或结束会话；结束会话不删除代码和 Codex 历史。

### 4.1 CLI 交互约定

本地只提供 `coc-agent` / `coc-client`，尽量共用代码并保持基础接口一致：

```bash
coc-agent login --relay https://relay.example.com --project /srv/project
coc-agent run
coc-client login --relay https://relay.example.com --message "请授权开发服务器"
coc-client hosts
coc-client projects --host build-server
coc-client connect --host build-server --project my-project
coc-client sessions
coc-client attach <session-id>
coc-client stop <session-id>
```

`connect` 创建会话并启动本地原生 Codex TUI。所有路径提示必须标注为远程路径。本地附件、剪贴板图片、外部编辑器等依赖本机文件的能力首版不支持，必须给出明确提示。

### 4.2 网页交互约定

顶部功能菜单分为 CW / 管理员模式，只显示各自功能，底部提供始终可达的模式切换按钮，短视口列表独立滚动。CW 提供会话记录、新建对话、工作区文件、会话详情与 CW 对话；管理员提供设备授权、API Key 与管理登录 / 退出，模式切换不改变权限、不退出登录或断开 CW 会话。默认 CW，设备授权链接进入管理员模式。聊天区最大化使用桌面 / 手机可用窗口，仅保留消息、输入及必要操作；主机 / 项目选择、CW 登录与授权操作集中在会话记录顶部的连接设置，列表位于其下方；会话记录和详情按需打开，并可立即收起。页面至少包含登录入口、主机/项目选择、会话列表和会话详情。CW 会话列表与远程 Agent 运行用户的 Codex 本地历史共用，按注册项目过滤，支持新建、恢复、搜索与分页；恢复必须校验原项目并继续强制服务器权限。详情页展示连接状态、任务状态、消息流、审批区及停止按钮；对话采用用户 / 助手聊天布局，支持安全 Markdown、表格与代码块，工具输出默认折叠。文本中的 HTML 必须净化，工具输出默认视为不可信文本。

CW 支持 `/model` 选择远程 Codex 返回的可用模型；下一条消息生效、按会话隔离保存，执行或提交未确认时禁止切换。命令本身不得发送给模型，不改变权限策略；外部会话在原客户端切换。发送任务后立即显示发送状态，按确认、收到回复、本轮完成、审批及连接异常更新，不将未确认提交显示为已成功执行。

CW 必须在浏览器保存当前主机、项目与打开的会话，刷新后在验证当前授权及身份范围的基础上自动恢复，并复用已缓存历史及该会话草稿。离线主机恢复缓存只读视图，已移除项目或不再授权的主机不得自动恢复；更换凭证身份不得复用旧身份的会话选择。自动恢复不得自动接管控制权、创建新会话或重发待确认任务，存储故障不得阻止手动在线阅读。

CW 向上滚动接近消息区顶部时自动异步加载更早消息，防止并发重复读取，提供加载状态及失败重试；点击“加载更早内容”同样可读取。读取成功后，必须完整显示本次读取的消息并保留此前已显示的消息，连续加载不得因消息总条数或总字节上限而丢弃已加载历史；在线与缓存读取行为一致，保持阅读锚点。“返回最新内容”恢复有界实时窗口。

断线时禁用新任务提交并显示重连状态；恢复时先同步当前轮次和未决审批。审批按钮提交后等待确认，重复点击不得产生重复决策。首次加载只请求最近记录，历史记录分页读取。

## 5. 状态与恢复要求

连接状态和任务状态分别记录，不能因客户端断开将任务标记为失败。

- 主机：`offline → connecting → online`；被撤销时为 `disabled`。
- 会话：`starting → ready → closing → closed`；异常退出为 `failed`。
- 轮次：`idle → running ↔ waiting_approval → completed / interrupted / failed`。
- 客户端：`attached / reconnecting / detached`。

客户端断开后 runtime 默认保留 30 分钟；到期先请求中断，再关闭进程，记录原因。未决审批默认等待最多 10 分钟，到期拒绝并记录，适配器无法安全拒绝时终止该会话。Agent 重启后的历史恢复必须显式展示，不能假装进程从未中断。

## 7. 安全与数据要求

- Codex 登录凭据只保存在服务器，Agent 与用户访问凭据分开管理；CLI 凭据使用系统凭据库或权限为 `0600` 的配置文件。
- 使用 TLS；首版信任 Cloudflare 中继，**不提供端到端加密**。代码片段、命令和对话会经过中继，必须在部署说明中说明。
- 云端不持久化对话、代码或命令输出；远程服务器保存权威历史，CW IndexedDB 和 CC SQLite 保存已读取副本。关闭会话或撤销授权不等于删除这些数据；本地缓存需支持明确清理。
- 访问范围至少绑定所有者、主机、项目和会话；用户输入的 ID 不是授权凭据。
- 不默认关闭 Codex 审批与沙箱；服务端固定权限上限，客户端不能通过启动参数或 RPC 提升权限。
- 首版的项目白名单是入口约束，不能被宣称为强租户隔离；强隔离需另用容器/独立系统用户。
- 日志不记录令牌和消息正文；记录连接、授权、审批结果、异常和主动接管的元数据。

## 2026-10-24 稳定化补充

当前实现支持项目内单文件上传下载；不包括完整文件管理器。网络协议、认证凭证与本机缓存的版本分别管理。

- 会话目录按稳定 ID 游标分页，每页不超过 100 条/96 KiB；活动会话检查不扫描关闭历史。兼容旧列表接口只返回首个有界页面，新客户端使用 `paged=true`。
- 创建/任务的逻辑请求 ID 由操作层保存；提供结果查询。状态不明不自动生成新 ID 或重发任务。权威请求身份保留，不自动清理未确认副作用。
- 附着在事务内预约，Agent 在新控制端首帧到达时才激活新 epoch；拒绝接管保留旧控制端。CLI 不支持再次附着时在票据阶段拒绝。
- 原生 HTTP 统一 30 秒 deadline，覆盖可取消 DNS 子进程、连接、TLS 和 HTTP 读写；超时不等同于远端未执行。
- CW 必须常驻远程目标；审批有总高度预算；连续工具默认折叠。离线缓存、草稿、任务运行、控制权与提交结果分别呈现。
- 撤销通知立即关闭相关连接；授权缓存最多 5 秒，不再使用 alarm 周期复核。只读/网页消息有累计未确认字节预算；CLI 原生 RPC 的平台发送队列仍受运行时能力限制。

[实施及验证状态](stabilization-2026-10-24.md) 是本轮门禁记录；八小时负载、真实 DO 重建、真机/辅助技术与生产预发布检查不能由常规测试替代。

## 原生程序自动更新（0.5.2）

Agent/CLI 默认检查所连接中继发布的当前平台稳定版本，配置文件可以禁止或调整 1–168 小时间隔。只安装更高版本及相同协议；下载包必须通过 SHA256、目标和构建身份验证。Agent 等所有运行会话与历史读取结束才切换，CLI 在命令/TUI 结束后安装。网络/校验/权限故障不影响原业务结果，不能隐式提权；更新使用互斥、同目录原子替换并保留上一版，不修改凭据、Codex 或数据库。支持边界与回退要求见用户手册。

### 2026-10-25 性能实现约束

- 完整阅读窗口和本地历史保留优先于通过丢弃已读内容降低内存；性能优化采用批量写入、局部渲染与本地优先读取。浏览器自身配额或显式清理另行提示。
- 流式批量提交必须保持原始事件、正文、投影与游标的事务一致性，提交后才发布，不降低持久化级别或提前确认副作用。
- 文件流水线必须有界并协商兼容，按连续偏移发布，验证重试/重叠、文件版本与覆盖权限。慢文件工作不直接占用会话业务执行循环。
- 中继按接收者保持事件顺序和容量约束；鉴权缓存/并发合并不延长凭证有效期或接受已撤销的在途结果。

## 外部会话支持（0.5.7）

允许观察同一用户 / CODEX_HOME、匹配授权项目目录的外部终端和 IDE 会话；不能争抢 writer。默认只读；入队要求 workspace-write 且 externalSessions.allowQueue 明确开启。外部执行沿用原客户端策略，Agent 不声称能约束外部权限。必须区分 queued 与 executed、保持请求幂等、支持未知结果恢复及历史稳定 revision；断开观察不得中断原任务。

### 无人值守审批

支持非 coc-agent 创建且位于原共享 app-server 的外部会话，将命令、文件与本轮权限请求转发到已授权 CC / CW；需要 allowApprovals 明确开启及 workspace-write。必须显示接入状态，验证原线程已加载和项目一致，避免用新进程假装处理原审批。只有独占 stdio 的已有进程不能实现事后审批接入；MCP / 工具表单及设备身份验证有兼容性边界。重复决定、原客户端先回答、断线及停观察不得重复执行、扩大授予范围或自动拒绝原请求。

### 配置可编辑性与外部输出补全

Agent 登录生成的 JSON 必须包含全部可选配置的默认值，嵌套配置显式展开；补全不覆盖用户已设置的值。Windows 审批必须明确配置连接原服务的本机 WebSocket，初始化失败提供可操作的具体原因。外部历史观察不得因尾部窗口推进而漏掉当前轮已观察消息的后续内容；同步保持分页、稳定条目身份和版本去重。

## CW 当前会话自动批准与管理表格

管理页面的待授权、设备、唤醒配置和 API Key 列表以原生表格展示，窄屏滚动局限于表格区域，并保留按行审批、目标锁定、保存及撤销。

CW 可由用户显式开启当前会话自动批准，默认关闭，包含命令、文件修改和本轮额外权限。设置由 Agent 按会话持久化，关闭网页后继续执行，刷新或重新打开后恢复；其他会话默认关闭。审批通道不可用时不自动放行，停止会话后关闭。不得绕过服务器上限、替代身份授权或修改 Agent 配置。未知、不支持及已提交请求不自动答复；重复同步、同会话重连和反复开关不得自动重复发送已尝试的决定。保留逐项手动操作及请求上下文。

## 访客 CW 与邮箱登出 · 2026-10-29

- `/guest` 及其资源、API、WS 提供完整访客流程，免 Access 邮箱认证，仅按原有 CoC 凭据授权；Cookie 名称和路径与普通入口隔离，普通入口不可被伪造访客标记绕过。

## 单 Agent 多项目管理（第一版）

- 同一系统用户只需一个常驻 Agent；同机不同用户可同时运行独立实例，hostId、配置、数据和 Codex 身份不得按物理机器合并。

- 文件系统隔离由操作系统保证，目录操作使用 Agent 系统身份，不要求 allowedRoots。现有沙箱及审批约束保留。
- 项目目录持久化、版本冲突检测、请求去重、活动会话移除保护、路径重复/重叠拒绝、退休 ID 防复用、不可用目录降级必须覆盖测试。
- 旧配置自动导入；旧 CLI projects 别名保留。注册新项目沿用实例级访问授权，不实现项目级 ACL 或跨 Agent 共享目录锁。
