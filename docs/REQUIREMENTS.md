# 项目需求与支持边界

项目通过 Cloudflare 中转，让 CLI 和浏览器访问没有公网 IP 的远程 Codex。远程 Agent 只建立出站连接，项目代码和 Codex 执行环境保留在服务器。

## 用户与组件

- `coc-agent` 管理当前系统用户的多个项目及 Codex 子进程。
- `coc-client` 提供原生 CLI / TUI 访问；CW 提供网页聊天、审批、历史、文件和终端工作台。
- Relay 负责身份、主机目录、控制租约及有界转发。
- 平台管理员管理设备与授权；Agent 管理员管理其目标实例的项目。管理身份与会话访问身份分别授权。

## 支持行为

## 一致性与恢复

业务使用 `delivery:2`。客户端先保存原请求，Agent 在执行前登记身份并预留容量，终态保存后回复，客户端提交结果后确认。断线仅恢复原身份；未知、过期或正文丢失均不代表业务未执行，不自动换编号重做。

Worker 不保存业务重放日志，授权与控制状态保存在原生 Durable Objects。授权在连接和逻辑通道握手时验证，后续撤销通过持久控制事件关闭失效连接。Agent 独立执行控制代际、RPC 允许列表、沙箱和审批校验。

`coc-agent run` 除用户明确停止外保持常驻：连接、鉴权、协议协商失败固定每 30 秒重连；初始化或运行故障在清理后每 30 秒重新初始化。认证失败不授权访问，存储故障不允许继续执行副作用；重新初始化必须通过原有配置、Codex、存储及实例锁检查。用户停止取消重试，受控更新与重启保留。

历史与遗留积压默认最多保留一周，容量压力可提前清理；活动执行和必要预留受到保护，仍受硬预算限制。CW / CC 缓存已读取内容及认证恢复凭证，按原 Codex 来源验证恢复，不保证永久备份。

## 安全与平台约束

- Agent / CLI 使用 C++17，运行无需 Node.js；云端和网页使用 TypeScript。支持 Linux x86_64 与 Windows x64，Terminal 仅支持具备隔离依赖的 Linux。
- CoC 隔离实例授权，系统用户的文件访问由操作系统限制。项目路径不允许重复或父子重叠；文件传输限制在登记项目内。
- 同一项目的任务与 Terminal 互斥；不同 Agent 对共享目录不提供跨实例执行锁。
- CLI 只允许声明的 RPC；账号/配置写 RPC、任意命令 RPC、附件和跨会话历史访问拒绝。平台远程配置走独立 owner 管理接口。
- 命令、文件与额外权限审批保留显式决定；当前会话自动批准必须主动开启，不绕过 Agent 策略。外部审批不得在不确定时隐式批准。
- TLS 验证、Origin 校验和 Cloudflare Access 可信 origin 约束必须保留。共享入口 Token 不能替代 CoC 业务凭据。

## 能力边界

CLI 不支持重新附着已附着的 runtime；Agent 重启不恢复旧进程。CW 可从同一用户和项目的 Codex 历史显式恢复线程，不自动重发任务。网页不支持补充问题 / MCP elicitation，会明确拒绝。

项目不提供文件同步、端到端加密、不可信多租户隔离或无限日志保留。终端不能访问网络、主机 HOME 或其它项目；其输出为易失缓存。源码支持不等于现场已部署，升级和验证见 [发布操作](RELEASE.md)。

启动失败自动诊断：Agent 的配置读取、验证、数据库/运行时初始化失败（进入运行循环之前），以及 Client 的本地配置初始化或 `attach` / `connect` 启动失败，会在每个进程内最多启动一次本机 `codex exec` 修复。Agent 等待诊断结束后继续原有 30 秒重试；Client 保留失败退出码，修复后需重新执行原命令。Client 会话启动诊断覆盖凭据加载、Codex 版本校验、连接请求、本地缓存/桥接初始化、TUI 创建和初始化前异常退出；`connect` 在创建远端会话之前先校验 Codex。认证与传输握手完成且 TUI 发出 `initialized` 通知后，视为进入运行阶段。参数错误、未选择主机、错误会话模式、TUI 正常退出、运行中的网络故障、普通命令失败和 `doctor` 检查结果不触发修复。需已安装、登录 Codex；会调用模型并可能计费。

诊断 Codex 使用 `danger-full-access` 与 `approval_policy="never"`，以当前系统用户权限执行，允许联网下载发布站 `/downloads/` 下匹配构建版本的源码、校验摘要，以及备份后修改本地 CoC 配置、升级 SQLite 数据库。该权限模式没有路径级强制隔离；提示词要求保留凭据、历史与任务，不放宽 TLS/认证/沙箱/审批，不删除数据库、不重启活跃会话、不部署云端。配置路径、构建身份和错误码进入提示词，配置内容和原始异常消息不直接注入；Codex 仍可在本机读取诊断所需文件。设置环境变量 `COC_NO_STARTUP_REPAIR=1` 可完全禁用；子进程自动继承此标记以避免递归诊断。Codex 缺失或修复失败时打印状态并保持原有失败处理，不视为已修复。进程不能执行（例如加载器/动态库缺失）、崩溃和初始化之后的故障不在此机制覆盖范围。

## CW 忙碌时排队

普通 CW 会话支持忙碌时持久化排队、顺序自动执行、取消未开始消息及指定消息立即执行。立即执行先停止原任务，等待真正结束后启动选中消息，保留其他消息顺序。请求重试不得重复入队或重复启动；排队与执行分别确认。队列跨浏览器刷新、断线和控制端接管可恢复查看，修改受现有控制权约束。停止失败或结果未知暂停调度；关闭/失败会话和 Agent 重启保留消息供核对，不自动恢复原 runtime 或重放未确认执行。外部会话沿用原客户端队列能力。
