# Agent 数据保留与客户端恢复凭证

## 数据放在哪里

| 数据                                                             | 保存位置与期限                                                   |
| ---------------------------------------------------------------- | ---------------------------------------------------------------- |
| 已读取的历史页、正文及恢复凭证                                   | CW IndexedDB / CC 本地缓存，沿用客户端有界缓存；不是永久备份     |
| Codex 已完成条目的原始内容                                       | Codex 自己的会话文件；Agent 按原 thread / turn / item 读取并验证 |
| Agent 历史正文、事件投影和逐条恢复映射                           | 默认最多一周；容量压力允许提前删除，无需遗留订阅显式释放         |
| 未决操作、未知结果、交付积压、旧信用流和上传完成回执             | 默认最多一周；压力提前清理可回收的记录，返回明确的过期错误       |
| 项目修改请求身份和结果尾部                                       | 一周及同样的容量水位；淘汰前推进项目 revision 屏障               |
| 活跃执行的数据与输出预留                                         | 执行期间保护；仍受既有硬预算约束，不因历史清理停止任务           |
| 身份、配置、项目路径、授权和当前会话目录                         | 保留必要权威状态；不作为历史正文清理                             |
| Agent 签名密钥、每项目随机代次、请求准入代次、单调序号和覆盖计数 | 少量恢复与防重放元数据，不能随正文一起删除                       |

已清空会话的历史头和 RPC 输出头压缩为会话目录中的少量计数，归还历史 scope / 输出流额度。活动会话目录、配置及项目文件不删除。仍由进程持有的上传临时文件沿用更短的空闲到期策略，删除成功并同步目录后才归还落盘预留。重启遗留的 unknown / 删除失败的 retired 上传回执也受一周及压力期限约束；回执淘汰不会扫描或删除来源不明的项目文件，项目内未登记暂存文件可能仍占磁盘空间。

## 默认配置

在 Agent JSON 的 `historyStorage` 中配置：

```json
{
  "historyStorage": {
    "retentionSeconds": 604800,
    "storageMaxBytes": 268435456,
    "cleanupThresholdPercent": 80,
    "cleanupTargetPercent": 60
  }
}
```

`retentionSeconds` 为 1–604800 秒，不能设成无限保留。`storageMaxBytes` 默认 256 MiB，统计 SQLite 已使用页，即 `(page_count-freelist_count)*page_size`；不是数据库文件、WAL、项目文件或安装目录的总大小硬上限。原有历史全局 / 单会话字节、条数、scope 上限，以及操作、输出、上传和项目账本各自预算仍生效。

各类预算达到 `cleanupThresholdPercent` 开始压力清理，以 `cleanupTargetPercent` 为回落目标；target 必须小于 threshold。维护及新操作准入会检查，普通调用合并至每秒一次，每类每轮最多处理 128 个对象。历史优先处理到期内容，再处理可回源及已交付内容，最后处理其它闲置内容；一轮或全部可回收记录用尽后不保证立即达到目标。运行中的任务及其必要预留不驱逐，控制操作另有独立预留；全部容量被活跃任务占用时仍会拒绝新任务。

命令交付分配在成功校验分配凭证或生成接收窗口后记录进程内活动时间，容量压力清理跳过最近 60 秒内活动的分配，防止两轮任务之间 `running=false` 时误回收正在使用的通道。该活动表受交付分配数量上限约束，回收分配时删除；重启后不保留，不延长创建时起算的保留期限。保护内无法回收至目标时仍按硬预算拒绝新准入。CW 仅在两条命令 lane 均无待发送 / 待确认命令且结果无缺口时，针对分配不匹配重新申请原 stream 的分配（保留当前控制绑定）；旧 lane 连同结果进入既有有界退休记录，不重放旧命令。其它错误及有待确认数据的分配不自动换身份。

`retainedRecords` 继续控制“显式释放后按条数退休”路径；默认 `0` 只关闭该路径，不关闭一周期限和压力清理。保留起点在创建记录时保存，不在打开存储时补写。SQLite 校验完整的当前结构，接受 `user_version` 为 `0` 或 `1`；结构完整的未标记库可直接读取，无邮箱会话仍可连接并绑定。缺列或不支持的格式返回 `UNSUPPORTED_STORAGE_VERSION`，不修改原库。空库初始化为当前结构并标记为 `1`；已有库不改版本、不导入原始事件或转换表。

删除释放的 SQLite 页可供后续写入复用，**不会自动 VACUUM 缩小文件，也不等于安装目录立即变小**。已有文件空洞、WAL、磁盘写满 / I/O 故障仍有独立限制。不要对运行数据库手工删表、删行或用旧二进制回退新库。

## 客户端凭证如何恢复

Agent 对可验证的 Codex 条目生成 `contentReference.recovery`，载荷包含原引用、来源、重建参数、客户端身份及项目随机代次，以持久密钥做 HMAC-SHA256。客户端不能修改身份、项目、正文摘要或片段边界；载荷不是加密文本。Agent 不逐条保存已发凭证；普通历史分页附带凭证，CW 保存事件，CC 的 history 分页保存引用。

正文被清理后，客户端带原凭证读取。Relay 先验证当前权限并注入真实身份，Agent 再检查 MAC、Agent 实例、账号、项目、thread 与项目代次，通过只读 Codex adapter 读取原 turn / item，并核对实际来源、长度和摘要。凭证本身不能授予项目访问权；不能把不同来源或新内容冒充原正文。

CW 收到历史缺口时保留已缓存正文，将旧事件放入每会话最多 2048 条 / 4 MiB 的有界归档，并恢复当前快照；草稿、命令 outbox 和检查点仍事务保存。较早分页和正文展开可使用这些客户端记录。客户端缓存被删除、浏览器配额不足、来源条目缺失或 Agent 密钥丢失，均可能导致旧内容无法恢复。未加载的数据不会自动完整下载。

## 哪些内容清理后可能消失

Agent 自己生成的告警 / 诊断、审批与控制交互的特定证据、未写入 Codex 的事件细节、RPC 原始通知、尚未送达的结果及上传中间状态，没有保证可从 Codex 重建。客户端已收到并保存的部分可继续查看；未收到或未保存的部分在一周到期或压力淘汰后丢失。Terminal 原始字节仍沿用现有易失环形缓存，不新增长期归档。需要长期保留的对话请导出已加载内容，项目文件和 Codex 原会话另行备份。

## 过期不代表可以重新执行

业务请求的 `operationInstance` 与稳定的 `deliveryInstance` 分离。清理业务请求或上传回执时，Agent 在同一事务中推进准入代次；仍存在的旧请求只能查询 / 确认原记录，缺失的旧请求返回 `REQUEST_EXPIRED`。CW / CC 保存原请求和原代次，终止它的自动恢复并提示，不给它换代次自动重发。独立的新请求重新 probe 获取当前代次。客户端分别保存稳定 Agent 身份和请求代次；上传 status / chunk 及 Terminal 接收端绑定稳定身份，finish 等新请求获取当前代次，原请求恢复仍坚持原代次。

项目目录以单调 revision 屏障实现同样规则，旧信用流保留单调分配边界；清理失败时删除与屏障一起回滚。历史订阅被清理后返回 `HISTORY_SUBSCRIPTION_EXPIRED`，客户端建立新订阅并保留已提交历史；真实 Agent 实例变化、校验失败或存储倒退仍停止恢复。

CC / CW 必须从 probe 取得 `operationInstance`，不能用稳定 `deliveryInstance` 替代；缺少该能力返回 `UPGRADE_REQUIRED`。过期、`RESULT_UNKNOWN` 或 `CONTENT_EXPIRED` 都不能证明业务没发生；先核对当前会话、项目目录和文件，再决定是否提交新的业务意图。

## 历史预算配置

配置与校验由 `native/src/common.cpp` 的 `history_storage_config` 和 `packages/protocol/src/index.ts` 的 `historyStorageSchema` 定义。配置重启生效，未知字段拒绝。

| 字段                                      | 默认值               | 含义                                           |
| ----------------------------------------- | -------------------- | ---------------------------------------------- |
| `maxBytes` / `maxSessionBytes`            | 268435456 / 67108864 | 全局 / 单会话历史逻辑字节                      |
| `maxRecords` / `maxSessionRecords`        | 250000 / 64000       | 全局 / 单会话记录                              |
| `maxSessions`                             | 1024                 | 非空历史作用域                                 |
| `minFreeDiskBytes`                        | 536870912            | 新操作准入的可用磁盘下限                       |
| `writeWindowBytes` / `writeWindowRecords` | 1048576 / 256        | 受控输出预留窗口，默认随较小单会话预算收紧     |
| `cacheMaxBytes` / `cacheMaxSessionBytes`  | 67108864 / 16777216  | 可重建正文缓存子预算，默认随总预算收紧；允许 0 |
| `cacheTargetPercent`                      | 80                   | 可回源缓存分批回收目标，范围 1–100             |
| `readPageMaxBytes`                        | 1048576              | 单次 Codex 正文响应序列化上限，范围 1–1048576  |
| `readConcurrency`                         | 2                    | 正文回源并发，范围 1–4                         |

单会话预算不得超过全局预算，缓存不得超过对应历史预算，写窗口不得超过单会话预算。字节记账包含记录开销，不等于 SQLite 文件大小。传输正文分页仍受独立帧与字符数约束。

## 存储与背压

小正文优先保留单份内联投影，增长后转为分块；小 delta 合并为有界尾块，后台分批合并和去重。原始事件副本在持久投影覆盖后回收，可重建正文在来源验证通过后按缓存策略回收；单调水位与防重放屏障独立保留。

会话创建、任务发送和外部入队在副作用前预留历史容量。受控任务无法容纳当前输出时停止对应进程，保留已接纳输出并标记不完整，不代表任务从未执行。外部历史同步满额时回滚本次导入、保留分页位置并只读重试，不停止原外部 Codex 客户端。真实磁盘 / SQLite 故障拒绝新副作用，不虚报落盘成功。

验证入口见 [测试说明](TEST_REPORT.md)，其它资源预算见 [状态与资源](TRANSPORT_STATE_INVENTORY.md)。

## CW 存储不足时的恢复

普通历史缓存继续使用 64 MiB 全局 / 16 MiB 单作用域预算。浏览位置、草稿、待确认输入、模型及历史订阅记录可使用额外 4 MiB / 4096 条全局、1 MiB / 128 条单作用域恢复预留；这些记录仍记入原账本，历史内容不能消费预留，不需要迁移 IndexedDB 格式。命令 outbox 沿用独立预算。

订阅检查点事务因逻辑缓存背压或浏览器 `QuotaExceededError` 失败后，保留原订阅证明，停止该订阅的确认与释放，并在当前 WebSocket 上继续在线分页和接收事件；当前页面的内存水位不充当持久确认。重连后沿用此在线读取方式，清理本机会话缓存后重新建立订阅。订阅身份被其他页面修改、水位回退及认证错误仍停止自动恢复。写事务以 abort 的最终原因报告错误，避免过早读取空的 `tx.error` 丢失配额异常类型。

运行中事件或历史快照写入也统一触发配额降级：暂停本次会话的历史页、事件和正文块写入及订阅确认，避免每条新事件反复重试失败写入；在线读取继续，清理本机会话缓存后恢复尝试。实时写入在 400 条 / 192 KiB 的待写批次满时立即提交，不必等 20 ms 定时器；最多一个在途批次加一个待写批次，仍超出预算时保留原持久水位并明确提示写入积压。额度耗尽、写入积压与存储访问故障分别显示，访问故障保留具体错误原因。
