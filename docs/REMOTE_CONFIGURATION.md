# 在线进程的远程配置与重启

平台管理员进入管理页面的“杂项 → 远程配置与重启”，选择主机，点击“刷新在线目标”。列表显示支持 `configuration-v1` 的 coc-agent 和当前在线的 coc-client，包括版本、PID 和本地配置文件路径。不支持该能力的端点不显示为可管理目标。

点击“读取配置”，编辑或粘贴完整 JSON，再点击“完整替换配置”。这是替换整个文件，不是字段合并；目标端校验配置后保存原文字节，保留未知字段和格式。JSON 必须是对象且不超过 64 KiB。Agent 沿用启动配置校验；客户端校验 version 2 凭据目录、条目、所选身份、代理和更新选项。校验不能证明新凭据有效、远端可达或所有启动依赖可用。

成功替换后，点击“远程重启”并确认中断提示。文件修改在重启后生效；原命令行选项仍优先于文件。Agent 会关闭当前 runtime，重新执行原启动命令。coc-client 会关闭当前 Codex TUI、释放连接，再重新执行原启动命令；例如原命令是 `connect`，它可能创建新会话，不能把重启理解成恢复原会话或仅刷新界面。

客户端只有在使用所选主机身份进行在线 API / 历史操作期间建立管理连接，长时间运行的 attach / connect TUI 可持续管理；退出后无驻留后台进程，无法再读取、替换或重启。只修改其启动时实际选择的凭据文件，不接受远程指定任意文件路径。配置文件中其它主机条目也会随完整文件一起替换。短命令可能在管理员操作前已经退出；正在执行的有界端点 / 历史请求会在返回或超时后处理进程重执行。

读取与替换使用文件 SHA-256 版本进行比较；发现本地或其它管理员改动时返回 `CONFIG_CONFLICT`，应重新读取并核对修改。并发修改保护依赖相同的文件锁，不使用该锁的外部编辑器应避免同时改写。写入沿用私有临时文件、原子替换和配置锁，Linux 文件权限为 0600，Windows 文件沿用仅当前用户与 SYSTEM 的私有 ACL。每次替换在目标机器保留 `<配置文件>.remote.previous`，内容为替换前的完整原文；新配置导致无法联网时，需要在目标机器恢复该备份并重启。

配置包含凭据。管理员须显式点击读取；页面编辑器不写入 localStorage、sessionStorage 或 IndexedDB，使用完可点击“清除页面中的配置”。Worker 只转发端点密文，配置原文和回复不进入 Worker 内存、DO、WebSocket attachment 或云端日志。配置仍存在于管理员浏览器内存和目标文件 / 私有备份中。

远程写入和重启带独立请求编号。目标端在 `<配置文件>.remote/` 持久保存摘要及结果回执，不保存配置原文；重试同编号不会再次替换或重启，同编号不同参数拒绝。写入中断可以通过当前文件摘要确认是否完成，不能将未知结果盲目重放。回执用于本地长期去重，不应在确认请求前删除。重启请求先登记回执再确认，保证至多一次；若进程在登记后、实际重启前崩溃，该编号不会自动再执行，需要核对在线状态后明确发起新请求。

30 秒内未收到回复，页面保留原请求和编号，点击“重试原请求”继续确认。coc-client 的随机进程实例标识在断线重连和受控重启后保持，因此在认证凭据保持不变时，可以把同编号请求发送到重连后的同一客户端；Worker 的目标标识同时绑定凭据摘要，不能用其它凭据冒充。独立启动的客户端使用不同标识。重启回执只证明接受请求，不能证明新进程启动成功；应刷新在线目标，查看重新上报的 PID / 版本。页面重载会清除内存中的编辑器和未确认请求，不应把失去回执当作操作失败。

在线目标目录使用 `/api/v1/admin/hosts/:hostId/connections`，只列连接目标 ID。网页随后通过加密通道向每个目标请求 metadata，取得版本、PID、路径与能力。配置业务路径 `/admin/hosts/:hostId/configuration` 位于通道内，请求接收 `{ target, command }`，command 支持 `read`、带 `requestId/revision/text` 的 `replace`、带 `requestId/revision/allowActive` 的 `restart`；旧明文 HTTP 入口返回 `UPGRADE_REQUIRED`。

Worker 仅准入 owner 配置连接并绑定可信权限；Agent/CLI 端点检查有效期与权限后执行，失效确认会退休旧绑定。普通 CW、CLI、项目管理身份无配置权限。CLI 上行 `/ws/v1/client-management/:hostId` 仅注册该主机的在线进程与公开握手材料，不支持会话 RPC。回复绑定实际加密端点，其他客户端不能代答；Worker 重建关闭通道时，调用者按原编号重试。

CLI 的进程实例标识同时用于 attach claimId，受控重启复用该身份，避免误判为新控制竞争；一次性连接 ticket 可更新，控制 epoch 不因普通重连或同一 claim 重试而增加。

本功能不会开启自动升级，也不部署任意二进制。发布下载与实际进程升级仍遵循仓库现有 CI、校验和空闲安装规则。
