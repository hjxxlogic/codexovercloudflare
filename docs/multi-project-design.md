# 单 Agent 多项目设计

状态：设计及实现说明，2026-10-30。

## 目标与边界

同一系统用户运行一个常驻 coc-agent 管理多个目录。同一电脑的不同系统用户可以同时运行自己的 Agent；实例身份使用 hostId，不按机器名、IP 或硬件标识合并。凭证、配置、数据库、Codex 登录和本地控制入口按实例分离。

CoC 负责实例访问授权；文件系统隔离由操作系统保证。目录操作始终使用 Agent 的系统身份，不提权，也不要求额外配置 allowedRoots。管理员身份不能绕过系统文件权限。现有 Codex 沙箱、审批、项目文件访问限制保持有效。不同 Agent 访问操作系统允许的共享目录时不提供跨实例文件锁。

## 用户接口

- `coc-agent project list|add PATH|rename ID NAME|remove ID` 管理当前配置对应的实例。
- `coc-client project list|add PATH|rename ID NAME|remove ID --host ID` 管理远程实例；PATH 是远程路径。
- add 支持 `--mkdir` 创建目录、`--name` 指定显示名、`--project-id` 指定 ID。
- `project browse PATH` 仅向管理员列出目标系统用户可以访问的目录；CW 提供相同目录选择功能。
- 保留 `coc-client projects` 列表别名。
- `coc-agent admin-email EMAIL` 关联一个管理员邮箱，空字符串解除关联；平台管理员可通过 CW 设置覆盖值或恢复 Agent 配置。
- 首次登录不再要求 --project；保留该参数用于同时登记首个项目。

CW 在连接设置和平台管理页提供项目管理入口。操作成功刷新目录；失败保留输入并显示原因。管理界面明确显示目标实例、远程路径，以及移除项目不会删除文件。

## 身份与管理授权

本机用户通过受系统文件权限保护的本地控制入口管理自己的 Agent。远程管理允许以下主体：目标 Agent 关联管理员邮箱的已验证身份，以及 CoC 平台管理员。普通实例访问者可查看和使用登记项目，不可更改项目目录。访问邮箱 accessEmails 与管理员邮箱 adminEmail 分开。

管理员邮箱身份必须来自 Cloudflare Access 验证和服务端账户绑定，不接受客户端自行申报邮箱。CC 使用 `login --manager --host ID` 发起明确的管理身份配对，在浏览器由对应邮箱管理员或平台管理员确认配对码。普通配对审批不升级为管理身份；本机 Agent 的普通 approve 不能代替邮箱身份验证。管理 CC 的权限每次请求重新核对当前邮箱关联或平台管理员版本，撤销关联后立即失效。

平台管理员可以管理全部实例的项目，不因此取得会话控制或机器 root 权限。新增项目沿用实例级访问授权：已有实例使用者可使用新增项目；第一版不引入项目级 ACL。

## 持久化与执行

Agent 是项目目录的唯一执行者。项目登记存放 dataDir/projects.json，包含项目、单调 revision 和有界幂等回执，原子替换写入。首次使用从 agent.json 的 projects 导入，之后该字段只作为初始配置。允许空项目启动，项目登记无固定数量配额；实际响应仍受协议帧大小约束。项目 ID 不随名称变化，已退休 ID 不允许复用。目录记录绑定 hostId，防止误用其他实例的数据目录。

在线本机命令通过绑定 127.0.0.1 随机端口的控制通道提交；随机认证令牌保存在实例私有数据目录，连接有大小、数量和时间上限。没有常驻 Agent 时，本机命令取得同一实例状态锁后直接管理目录。无法取得状态锁时不得离线修改或绕过正在运行的 Agent。

远程管理通过 Relay 已鉴权控制请求进入同一个执行函数。列表返回 revision；变更必须带预期 revision 与 requestId。请求去重先于版本比较；相同 ID 不同内容拒绝执行。回执保留最近 64 次成功变更；之后旧 revision 仍阻止陈旧重试执行。原子保存目录和回执，避免崩溃后重复登记。mkdir 是显式副作用；遇到保存失败可能留下空目录，不自动删除用户目录。

新项目路径规范化，拒绝与本实例已登记路径重复或父子重叠。运行会话固定项目路径。暂时不可访问的目录显示 unavailable，不阻止其他项目启动。改名只修改名称；第一版不支持修改路径。移除仅取消登记，有活动会话或文件操作时拒绝；历史数据保留且不转移给新 ID。

变更后通知客户端刷新目录，不重启 Agent、不终止其他项目任务。远程操作需要 Agent 在线；离线缓存不能用于宣称操作成功。

## 兼容、验证与交付

旧 projects 配置自动导入，原 ID、路径和历史关联保持不变。降级前需停止实例并将当前目录导回 agent.json，否则旧二进制会使用过时的初始化数组；项目文件和历史不自动回滚。协议新增管理操作；旧 Agent 明确返回不支持，不静默退回修改配置。现有项目查询和会话流程兼容。

验证涵盖：空项目登录；多个目录并行使用；在线/离线本机命令；版本冲突、重复请求和重启持久化；活动会话移除保护；目录失效；路径别名与重叠；管理员、普通访问者及跨实例拒绝；邮箱关联变更和管理 CC 失效；平台管理入口；同机两个实例独立运行。更新 USER_GUIDE、ARCHITECTURE、REQUIREMENTS、TEST_REPORT 和 CHANGELOG。运行原生、协议、Relay 和界面相关测试及静态检查；部署另行遵守 CI 制品流程。
