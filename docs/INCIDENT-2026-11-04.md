## 已复现的缺陷与判断边界

`apps/relay/src/registry.ts` 对授权变更广播到所有 Host；`apps/relay/src/host.ts` 的 `authorizationChanged()` 清空正在进行的校验并推进授权代次。当两次刷新交错时，较早的成功校验仍会在 `authorized()` 内因代次变化抛出 401，随后刷新逻辑以 WebSocket 4001 关闭有效 Agent。`native/src/agent.cpp` 将所有 4001 解释为设备授权撤销，正常退出。

隔离复现让两次 Registry 校验均成功返回永久有效期，仍观察到 Agent 被以 `4001 / Authorization changed` 关闭，且连接标记为 retired。复现仅运行本地内存测试，没有对线上发送授权变更或模型任务。

这一竞态与线上多机退出、凭据仍有效、服务不重启的现象一致，是本次批量离线的主要代码层嫌疑。尚未获取事故时刻的云端调用日志，不能确认具体哪次管理操作或广播重试触发，也不能据此把所有历史离线归于同一原因。实时 Wrangler tail 因执行环境网络连接超时未建立。

## 恢复与修复建议

先修复授权刷新竞态：旧代次结果应重新校验或使连接可重连，不能被当作确定撤权；保留对真正撤权的立即隔离。同时缩小广播范围，并检查无实际变更时是否仍需广播。修复需要覆盖交错刷新与真实撤权两类测试。

恢复时核对各实例状态，再启动已退出的 Agent，沿用现有凭据、配置及数据，无需重新注册。仅启动现有进程不能根治竞态。不要重启仍在线的实例或自动重放退出前的任务。本次仅诊断，没有部署、修改授权、启动 Agent 或调用模型。

机器证据保存在忽略目录 `.local/incident-2026-11-04/`：管理状态快照、原凭据状态校验、退出时段日志、本地隔离复现源码与结果。包含私人配置的原始管理响应不纳入提交。
