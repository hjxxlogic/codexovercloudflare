## 本次落实的优化

### 缩小 Registry 通知范围

原 `publish('registry')` 在没有指定申请目标时遍历全部有效主机。登录 / 退出、API Key 创建、无目标申请及其到期都会唤醒全部 HostRelay，写入各自 revision，并可能使 CW 读取多份权威快照。每次无关管理变化产生最多五次 Host 请求及后续读取，管理通知还会反向触发订阅者活动鉴权。

现在管理员和本申请订阅仍更新，Host 通知按操作确定范围：

| 变化                                                 | Host 通知范围                              |
| ---------------------------------------------------- | ------------------------------------------ |
| 管理登录 / 退出、API Key 创建、无目标申请开始 / 拒绝 | 无                                         |
| 指定目标申请、批准 / 拒绝 / 到期                     | 原目标                                     |
| 无目标申请批准                                       | 批准后绑定的主机                           |
| 未领取批准结果到期                                   | 原目标或批准绑定的主机，继续执行原权威撤销 |
| 主机唤醒配置、实例名称、API Key 登录                 | 对应主机                                   |
| 凭证 / API Key 撤销                                  | 受影响主机，同批去重；原主动断开路径保留   |
| 版本发布                                             | 所有有效主机；重复同版本同提交仍不广播     |

待批准 Agent 的 hostId 只是预分配 ID，到期时不为它创建新的 HostRelay。通知失败仍依赖现有快照恢复，不增加重试 alarm。`registry_change` 新增 `notifiedHosts`，便于后续观察目标数量。五主机情况下，无关管理变化的 Host 通知由五次降为零，单主机变化由最多五次降为一次；这是代码路径差异，不是线上节费百分比。

### 跳过重复迁移完成检查

原每次 Registry / Host fetch 都读取 `expiryMigration`，即使迁移已完成。现在在同一 storage 实例中确认持久完成后保留 WeakSet 提示，后续请求跳过该读取。休眠重建重新读取，未完成迁移仍按每页 64 项继续，最后一页提交成功才设置提示。

同一已完成迁移的实例连续十次检查，存储 get 从十次减少到一次；实际减少的 SQLite 行读取受平台缓存及休眠频率影响，不按请求总数估算账单收益。没有扩大鉴权缓存、关闭 TLS 或调整授权 / 到期策略。
