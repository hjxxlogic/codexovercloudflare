# 性能修复记录 · 2026-10-25

针对 [性能审核](perf-audit-2026-10-25.md) 的 0.5.4 发布前实现和验收。基线为 `eae289c916cada30a5aef1b02f6225b9b082d4f3`，本记录对应其后的性能修改。下文为本地验收证据，未使用生产或模型任务；实际发布记录见 [测试记录](TEST_REPORT.md)。

## 完整历史和本地优先

按用户明确要求，完整历史阅读是支持行为。已加载的全部消息和已展开的正文均保留，取消正文的 128 Ki 字符裁剪；不采用审核最初提出的历史页面环淘汰或正文 LRU。审核 F02 的建议和验收目标已据此修正。

浏览器 IndexedDB 持久保存已读页、消息修订与内容块，取消应用层自动修剪。旧页及正文先查本地，记录原始分页边界，支持从覆盖当前游标的缓存页提取子范围；返回最新再翻旧页不重复下载。只向服务器请求本地缺失页/正文，以及重连后的新消息和修订。浏览器配额失败会提示，用户仍可显式清理单会话缓存。最新实时窗口仍采用既有 400 条/192 KiB 上限；它不裁掉历史阅读窗口。

完整阅读的 DOM/内存会随用户加载量增长，本轮没有把固定内存当作验收目标，也没有预取整个远程会话。原始数据仍由 Agent 权威保存，浏览器并非唯一副本或完整离线 PWA。

## 验证

- 原生 Release 构建：Ubuntu 20.04 与 Bookworm 容器通过。CTest native-core 1/1 通过，包含 128 条交错 Unicode 增量完整重建、批次异常整体回滚、缓存 SQL 在异常后继续使用、上传过期索引清理、乱序上传和冲突检查。
- `npm run typecheck`、`npm run lint`、`npm run lint:cpp` 通过；Vitest 六文件共 50 项通过。新增 Relay 覆盖同凭证鉴权合并及撤销竞态、慢接收者隔离与单通道订阅、alarm 凭证去重。
- `npm run test:cache` 使用独立 Chromium 和本地路由拦截：两个相邻 scope 各 3000 条事件，520 个正文块；超过旧 2000 条/512 块限制的数据仍保留且可重新打开。1000 个同消息修订只发起一个写事务；显式清理访问本 scope 的 3524 条记录，保留另一 scope、草稿和待确认身份，也不让排队实时写入复活已清理历史。
- `npm run test:ui`：完整显示 600 条历史，超过 400 条/192 KiB 后仍保留全部记录及锚点；返回最新再翻旧页不增加历史网络请求。新增 34 次、每块不超过 4096 字符的正文展开，合计 131078 字符，检查原始前缀及全部正文相等。既有草稿、审批、管理员模式和移动布局回归保留。
- `npm run test:e2e`：无外网 Bookworm 容器内，真实 Wrangler/DO、原生 Agent/CLI、Chromium 与确定性 Codex 夹具通过。覆盖多块二进制文件、目录/版本/覆盖策略、历史恢复/本地缓存、重复任务去重、审批/接管、原生协议路由、授权隔离、撤销和 Agent 重连。原生 Codex 模型任务不在本轮范围。
- Web 生产构建完成，主 JS 439.43 kB，gzip 136.09 kB；不是首包体积优化。Worker 使用 `deploy --dry-run` 仅验证打包。

浏览器和原生回环测试需要沙箱外的本地进程通信；使用独立临时目录与隔离 context。端到端使用 `/tmp` 源码副本，不挂载生产凭据，测试构建身份标记为工作区未发布状态。可复现命令见 [开发指南](DEVELOPMENT.md)。本机临时证据为 `/tmp/coc-perf-ui-2026-10-25`、`/tmp/coc-perf-final-e2e.log`，不是永久制品。

## Store 对照基准

四组批量场景约 1.18 万–2.07 万 events/s，逐条场景约 1467–1602 events/s，显示密集流量下批量事务可减少固定成本；不能把这个比例当作真实 Agent 的收益倍数。单次样本且宿主为共享环境，原审核与本轮单条结果存在波动，不做跨轮百分比结论。基准复用同一源码路径，未分别隔离 SQL 缓存、小正文优化和 group commit 的收益。

128 条模式的 P95 是整批同步调用延迟（约 10–27 ms），不是单事件 P95，亦不含 Agent 10 ms 收集、业务排队和网络/浏览器时间；该模式尽量攒满批次，实际稀疏输出常会提前由定时器提交。所有场景只在结尾核对每会话最多 4096 字符；完整 Unicode 重建由独立回归覆盖。峰值 RSS 均为 11648 KiB；WAL 是离散采样、会复用，不能用文件大小代表总磁盘写入量。

## 尚未完成的性能验收

本轮没有宣称四会话八小时长稳、慢盘/锁等待下停止和审批 P95、100 页移动设备输入/滚动延迟、100 万请求库维护 P99、20/100/200 ms 公网文件吞吐或 Cloudflare 24 小时唤醒/账单达标。原生 CLI 的平台出站缓冲和 DO 重建/休眠仍有既有边界；需要受控环境测量及必要的自有桥接流控设计。以上属于尚未验证或需后续设计的项，不能由功能测试和短基准替代。
