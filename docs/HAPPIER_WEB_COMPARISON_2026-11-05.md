# Happier 官方 Web 实测对照（2026-11-05）

## 实测对象与方法

实际访问 [cloud.happier.dev](https://cloud.happier.dev/)，创建独立测试账户，通过其真实 Web 页面完成操作和截图。设置页显示 Web 版本 **0.2.19**。源码移植基线仍为固定提交 `d515b5547a1a3aa03e3141ddb6a45f4a72ae1025`；不据此断言线上源码与该提交完全一致。

登录、设置、空列表及已有会话可直接在 Web 中打开。要产生真实运行、工具事件和审批，需连接执行端。本次仅为生成对照数据安装官方 Happier CLI **0.2.20**，使用独立安装、状态、浏览器 profile 和示例项目；没有安装全局 daemon 服务、修改 PATH、替换 CoC Agent 或连接 CoC 项目。CLI 配对后，第二个任务直接从 **Web 输入框**发送，比较对象始终是官方 Web 的渲染和交互。

补充验证：两个任务完成后停止隔离 Happier daemon 及其测试会话，再从 Web 打开第一个会话；页面显示执行机器离线，但完整 Markdown、表格和工具历史仍可阅读。这实际确认了“查看已有会话无需运行 CLI”，并将查看历史与运行新任务区分开。安装、账户和原始证据继续保留在隔离目录。

官方公开二进制经 GH-Proxy 下载加速；保留安装器的 SHA-256 与 minisign 校验，均通过。账户密钥、浏览器状态、原始日志和完整测试会话 ID 仅存忽略的 `.local/happier-live/`，不随文档发布。

## 真实会话场景

| 场景             | 实际操作                                                               | 观察                                                                        |
| ---------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 无会话 / 新建页  | 新账户打开 Web，连接执行端前后查看新建页                               | 无执行端时显示连接引导；连接后提供目录、模型和权限选择                      |
| 单会话           | “格式化与工具调用”：读取 README 与示例文件、终端输出、修改一个函数     | 只有一层标题，工具作为紧凑时间线，正文与输入框共享阅读列                    |
| 文件审批         | 模型请求修改 `src/demo.ts`，Web 展示差异；仅点一次 Yes                 | 审批紧邻输入区，显示文件名、增删行与操作；没有选择整会话免审批              |
| 多会话           | 创建“多会话切换示例”；在 Web 侧栏依次点击两个会话                      | URL 和正文对应切换，侧栏保持可见，选中态清楚，行高约 34px                   |
| 富文本           | 真实模型回复标题、粗体、引用、文件链接、TypeScript、嵌套列表、表格     | 助手正文平铺；代码 / 表格独立表面，局部工具按钮弱化                         |
| 长工具输出       | 第二会话通过 Web 发起任务，终端一次读取 80 行长输出文件                | 工具行可展开，长输出内联展示；会话阅读容器滚动，输入区保持底部              |
| 长代码与任务列表 | 第二会话生成约 30 行 TypeScript，含约 180 字符长行及嵌套 checkbox 列表 | 代码可局部横向滚动；长行不会撑宽整个手机页面                                |
| 桌面 / 手机      | 1440×1000 与 390×844，真实浅色 / 深色设置                              | 桌面侧栏全高；手机单标题、返回入口与紧凑底部输入，页面宽度分别为 1440 / 390 |
| 设置             | 打开 Settings / Appearance 并通过页面选项切换浅深色                    | 灰色画布、白色分组行、细分隔、图标和 chevron，避免厚重卡片叠加              |

两次真实任务只访问隔离示例项目；只批准示例文件的一次写入。回归测试中的模拟 Codex 与这两次真实模型调用分别记录，不混称。

## 与 CoC 首轮页面的差距及实施决策

| 首轮 CoC 的问题                                            | 官方 Web 的实际做法            | 本轮调整                                                       |
| ---------------------------------------------------------- | ------------------------------ | -------------------------------------------------------------- |
| 原顶部导航、项目状态、新标题重复叠加；手机标题曾高达 154px | 单层约 56px 标题               | 合并为固定紧凑标题，状态保留在副标题，刷新 / 菜单为图标        |
| 侧栏从顶部旧导航下方开始，每会话多行重复元信息             | 侧栏从视口顶端开始，紧凑会话行 | 全高度侧栏，标题 / 图标 / 简短日期；完整目录信息保留在历史面板 |
| 用户消息右浮气泡、阅读列与输入列关系松散                   | 用户消息也在统一阅读列内       | 左侧整列浅表面用户消息，助手平铺，宽度约 818px                 |
| 输入框上方有重复表单标签、帮助文字及大按钮                 | 文字区与紧凑工具行，圆形发送   | 保留可访问标签，弱化模型与审批工具，圆形发送 / 停止            |
| 工具组和每条工具重复厚边框                                 | 轻量工具组与时间线             | 工具组浅表面、细时间线、详情与输出局部滚动                     |
| 管理页只是原有大卡片换颜色                                 | 设置画布与 inset 分组          | CoC 专用管理采用同一图标、字重、分组及桌面侧栏 / 手机 Tab      |

本轮只适配 CoC 已有功能。Happier 的 Direct、好友、收件箱、Git 编排、MCP、Agent 编排和账户恢复等按钮不复制为无效入口。Worker、Agent、业务协议和权限语义保持既有实现；会话切换、审批、历史和终端继续使用 CoC 回调。

## 验收与限制

除人工查看上述真实页面外，CoC 自动回归覆盖单 / 多会话、草稿、审批与自动审批作用域、工具懒加载、复杂 Markdown、文件 / Terminal、主题、手机阅读面积与管理全部九个面板。具体执行结果更新在 [实施记录](CW_HAPPIER_UI_PLAN.md) 与 [测试报告](TEST_REPORT.md)。

这不是像素级完整复制：官方使用 React Native Web 及其业务服务；CoC 保留 DOM 实现、自有品牌和管理能力。浏览器模拟手机视口，不等同于真机软键盘测试。官方页面出现过混合内容探测失败；选择 HTTPS relay 后实际登录、会话与设置操作正常，未绕过 TLS 校验。
