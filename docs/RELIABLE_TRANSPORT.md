# A / C 可靠传输协议

状态：0.5.18 协议实现与验收说明（2026-10-31）。C 包括 CW 与原生 CC；Worker / HostRelay 负责鉴权、序号登记和转发，业务执行仍由 Agent 负责。

## 用户确认的范围

- Worker 持久登记双方已发送的头序列号；每次命令转发都附带双方最新发送头，不能只在连接握手时发送。
- 双方在本机保存连续接收进度。观察到的最大序号与连续接收确认分开，不能越过缺口推进确认。
- 有副作用的命令使用类似 TCP 的滑动窗口，发送端保留未确认命令，接收端本地保留执行缓冲池。只有接收方发放的可用信用允许发送新命令。
- 无副作用的读取沿用原协议，由请求端在超时或临时失败后重试，不占用命令执行窗口。

## 身份与序号

逻辑流必须绑定主机、会话、设备授权身份、发送方实例和方向；不同主机、会话、设备、控制权代际不得混用确认或信用。发送方实例 ID 与序号持久保存，重建数据库时生成新实例 ID，禁止默默把旧流的序号重置为零。

发送头表示实际发布的最大序号，不能将只在本地排队、尚未获得信用的命令计入。接收进度表示已连续接收并持久化的最大序号，业务执行完成另行确认。Worker 登记发送头不等于接收端已收到，也不等于命令执行成功。

每次命令携带当前流标识、命令序号、双方发送头和接收进度。发送头在持久保存后再对外宣布；接收确认与对应数据在同一事务落盘后再发送。Worker 以最大值合并同一流的进度，拒绝无效数值、跨实例更新与过期控制权写入。

## 命令窗口

接收方信用由本地执行缓冲池的剩余条数和字节预算决定，不根据发送端对可用空间的猜测决定。信用带代际和单调边界；重复或乱序信用公告不会扩大可发送范围。命令已接收但尚未完成时仍占据执行缓冲；命令完成或明确拒绝后释放信用。

发送端在网络发送前持久保存命令及原请求 ID；窗口耗尽时本地排队并显示等待状态。发送端缓冲同样有界，禁止以无限内存替代背压。审批、取消等控制命令使用预留窗口，避免普通任务占满窗口后无法解除阻塞。

相同流、相同序号的重传必须具有相同请求 ID 和负载摘要。重复帧只返回已有确认或结果，不再次执行。乱序帧不能推进连续接收进度；缺口通过原身份补发。恢复只补发未被连续确认的命令，不生成新请求 ID。

## 执行与恢复

持久命令状态区分待执行、已开始、完成和结果不明。接收确认仅承诺本地持久化；执行完成确认引用原请求 ID。进程异常退出后，已经开始但无法证明完成的外部副作用不得自动重放，应返回结果不明并允许查询原任务。协议不宣称能够对任意外部程序的副作用提供跨崩溃的恰好一次执行。

历史正文与事件仍以 Agent 为权威，Worker 保存进度元数据，不新增长期历史正文存储。CW / CC 使用持久化连续接收位置与 Worker 附带的发送头核对，按缺口补取历史；查询失败由请求端重试。读取和补取不能取得写控制权，也不能重发任务命令。

## 兼容与验收

新能力必须显式协商；旧端未支持时显示兼容边界，不能声称已获得新协议保证。授权、沙箱、RPC 允许列表、接管规则与 TLS 验证继续生效。升级不得重启尚有活动任务的 Agent。

回归覆盖断连前后、丢失末尾更新、确认丢失、重复 / 乱序帧、信用耗尽和恢复、审批预留窗口、浏览器刷新、Worker 重建、Agent 重启、序号与授权隔离、未决副作用不盲目重执行。部署仍等待最终源码提交的所有 CI 必需作业成功，使用校验来源和摘要的制品。

## 线上帧与窗口

会话协商采用 `delivery: 1`，Agent 同时公布持久化 `deliveryInstance`。客户端发送 `delivery-open`，Worker 将外部流 ID 与授权 hash、会话、normal / priority 通道共同哈希，禁止跨设备复用窗口。每次业务命令及结果附带 `heads`：历史修订头、CC RPC 输出头，以及两个命令通道的发送 / 结果 / 接收头。Agent 结果中的自身持久进度也回写 Worker，因此最后一帧在 A 到 Worker 途中丢失后，后续读取仍能发现缺口。Worker 重建及活动 DO / 空闲 D1 迁移保留这些元数据。

命令帧包含 `stream / lane / seq / end / body`；body 保存确定的 JSON 文本，end 是累计 UTF-8 字节位置。Agent 接收窗口 normal 为 16 条 / 2 MiB，priority 为 4 条 / 512 KiB；发送端本地分别预留 96 条 / 1.5 MiB 与 4 条 / 512 KiB。信用使用绝对右边界 `credit / byteCredit`，旧公告不得收回已发放信用或增加可用额度。传输帧仍受 256 KiB 限制，检查包含 JSON 转义后的大小。

收到持久化确认后，发送端停止重发命令，改为使用原序号查询执行结果。结果在本地提交后才推进连续结果确认并移除待处理项。normal 阻塞不影响 priority 的审批 / 中断。Agent 的 SQLite 保存接收进度、负载和执行阶段；工作区历史清理不会删除未确认命令及 CC 输出确认位置。CW 使用页面生命周期锁区分复制标签页，并在刷新后恢复本标签页的发送缓冲，避免不同控制端覆盖同一缓冲。

CW 可通过受当前控制端证明保护的 HTTP 命令入口发送可靠帧，接收窗口和结果查询仍为普通读取。只读 `snapshot` 在会话 WebSocket 停滞时补回历史和当前状态，不获取控制权；读取请求最多作两次额外重试。只在有未确认命令或初始化握手时查询窗口，正常空闲不新增业务轮询。

原生 CC 对同一 TUI 的网络重连提交原控制端证明与逻辑流 ID；Worker 原子核验 owner、流与控制代际后才分配新租约，Agent 同时要求原可靠流匹配。新的 TUI 进程仍不能随意附着已经初始化的 CLI runtime。A 到 CC 的 RPC 输出另有持久日志和 32 条 / 2 MiB 窗口；CC 将有序输出交给本地 TUI、保存接收位置后确认，缺口按原序号补发。历史修订号、命令序号与 RPC 输出序号不能混用。

Agent 数据库实例 ID 或已确认接收位置发生不兼容变化时，发送端停止自动补发，防止把存储回退误当成丢包。进程重启后，尚未执行的缓冲命令明确失败，已开始而结果不明的命令保持 RESULT_UNKNOWN，不自动重复外部副作用。

本窗口处理建立会话后的模型命令、审批、中断、自动批准设置及 CLI RPC 写操作。项目变更、文件分块和会话创建 / 停止继续使用各自已有的请求 ID、版本检查、上传偏移 / 窗口和异步结果回执；读取、鉴权和配对不进入会话执行窗口。旧 Agent 未协商能力时继续旧会话协议，不能据此宣称已获得新可靠通道保证。
