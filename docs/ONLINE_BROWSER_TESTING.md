## 1. 目标与运行环境

目标网站为 `https://r.xlogic.cc`，预期管理员邮箱为 `huangjielg@gmail.com`。执行机器通过远程终端登录，无桌面环境；使用 Playwright headless Chromium，不依赖 DISPLAY、桌面浏览器或人工鼠标操作。

首次初始化由自动化打开真实 Access 登录页、填写邮箱并请求验证码，用户从邮箱取得验证码后通过终端输入或对话交给执行者，执行者将其送入**仍在等待的同一浏览器上下文**。完成认证后保存可复用的凭证快照。后续测试创建独立浏览器上下文并加载同一有效认证快照，无须每次输入验证码。

这是“首次或会话失效时人工参与”的自动化流程，不是永久免验证。Access 会话、CoC 会话、服务端撤销和边缘策略均可能使凭证失效。不得自动读取邮箱、绕过 Access、伪造身份请求头或使用管理员 Secret 替代本次邮箱登录验收。

## 2. 两层认证必须分别验证

当前实现依据：

- [Relay 入口](../apps/relay/src/index.ts) 的 `GET /api/v1/auth/email` 从受信任的 Access 身份读取邮箱，返回 `email`、`accountId` 和 `autoAdmin`。
- `POST /api/v1/auth/email/admin` 校验真实邮箱身份后建立 CoC 管理员会话，设置 HttpOnly `coc_admin` Cookie，当前 Cookie Max-Age 为 28800 秒（8 小时）。Cookie 有效期不等于服务端权限永远有效。
- [网页入口](../apps/web/src/main.tsx) 在 `autoAdmin` 成立时调用正常管理员登录路径，再读取业务身份。

初始化成功必须同时满足：目标 origin 正确、实际邮箱与预期一致、CoC 管理员身份成立、管理员只读接口可访问。仅看到首页、HTTP 200、Cookie 存在或 `autoAdmin=true` 都不能单独作为成功依据。返回登录 HTML 的 API 响应也不能当作 JSON 成功。

管理员浏览器测试不注入共享 Cloudflare Service Token；共享入口凭据不是邮箱用户身份，也不能证明真实邮箱登录路径通过。既有原生/脚本的 Service Token 测试作为另一类入口测试保留。

## 3. 无图形界面的初始化流程

1. 创建私有运行目录和新的 headless Chromium Context，打开明确配置的目标 URL。允许站点自身及已确认的 Cloudflare Access 登录域参与导航；异常域名或不可识别页面立即停止。
2. 检测登录表单，填写预期邮箱并提交一次。确认已经进入验证码页面后输出“等待验证码”，包括运行编号及等待截止时间，不打印 Cookie、页面源码或隐藏字段。
3. 保持浏览器与当前挑战状态存活。进程通过不回显的终端输入，或受控 stdin 接收一次验证码；不把验证码放进命令行参数、环境变量、JSON 配置、shell 历史或持久日志。
4. 用户可以在对话中提供验证码，由执行者送到该等待进程；程序不另行记录或复述验证码。对话本身可能保留用户发送内容，不能承诺聊天平台不留记录。
5. 在原页面输入验证码并提交，等待真实重定向和两层身份验证。完成业务登录后，关闭非必要页面，再提取认证快照。
6. 验证码错误、过期或页面挑战改变时，明确报告初始化未完成；不循环猜测、不自动重复发邮件。需要重发时由用户明确触发，后一次挑战取代前一次。
7. 如果出现 CAPTCHA、设备证明或其它不能由验证码解决的交互，停止并报告真实原因。headless 是执行方式，不承诺能通过所有 Cloudflare 防机器人挑战；不实施绕过策略。

等待验证码期间不能启动测试、构造测试业务请求或用新的浏览器 Context 提交旧挑战。等待超时或执行中断后关闭浏览器，下一次重新开始初始化；不声称一个旧验证码可跨挑战恢复。

## 4. 凭证快照与浏览器隔离

建议私有目录：

```text
.local/online-tests/
  auth/admin.json
  auth/metadata.json
  runs/<runId>/
```

目录权限 0700，凭证文件 0600，写临时文件后原子替换；纳入已有 `.local/` 忽略范围。凭证不提交、不上传 CI artifact，不出现在截图、错误摘要、trace、HAR 或网络头日志中。元数据只保存目标 origin、预期邮箱、生成时间和验证结果，不复制 token。

Playwright `storageState` 能保存 cookies、localStorage，并可选择保存 IndexedDB；本项目必须明确区分**认证快照**与**业务恢复快照**：

- 默认只导出经审计的 Access/CoC 认证 Cookie，以及确实必需的认证字段；保留 Cookie 的 domain/path/expiry/Secure/HttpOnly/SameSite 属性，不手工降级属性。
- 不复制 IndexedDB、outbox、未决请求、控制实例、历史订阅检查点、会话游标或已选择项目等业务状态。当前业务认证主要通过 Cookie，若发现必需的其它存储字段，应逐项审核后加入白名单。
- `sessionStorage` 不由标准 storageState 自动保存；不因某次登录失败就全量复制它。先判断字段是否确属认证，不能把任务恢复状态带入新测试。
- 各测试创建干净 Context，加载同一认证快照；不是多个进程共同打开同一 Chromium profile 目录。每个测试自行创建业务身份/流实例，避免重复恢复原请求。
- 多标签页用例在同一 Context 开多个 Page，测试真实共享存储和控制权行为；跨浏览器用例使用独立 Context，两种情况分开断言。
- 单一初始化/刷新流程持有文件锁；测试进程只读基线，不将每个用例结束后的业务状态写回认证文件。刷新用新版本快照服务后续运行，不在进行中的副作用测试中替换身份。

只允许管理员用例复用此身份。未登录、游客、普通用户和被撤销主体的用例使用各自独立状态，不能带管理员 Cookie 验证低权限行为。

## 5. 每轮测试的准入与过期处理

开始测试前：

1. 检查目标 origin 在显式允许列表内，读取线上版本/源码身份并写入报告，不将仓库 HEAD 当作当前线上版本。
2. 用新的 Context 加载认证状态，检查真实邮箱、业务角色和管理员只读接口；错误身份直接停止。
3. 核对配置的测试 hostId、projectId 和测试目录标记，确认属于专用测试资源，不能“找第一个在线 Agent”执行操作。
4. 需要写入的用例检查 Agent 在线、版本兼容、容量和实例身份；失败是环境前置条件不满足，不计为业务测试通过。

过期分层处理：

| 情况                                 | 行为                                                                |
| ------------------------------------ | ------------------------------------------------------------------- |
| Access 有效，CoC 管理员会话缺失/过期 | 在独立认证流程中走正常邮箱管理员登录路径，核验后更新认证快照        |
| Access 跳转登录或拒绝                | 标记 `AUTH_REQUIRED`，暂停业务测试，提示人工重新初始化              |
| 身份有效但目标资源拒绝访问           | 记录权限/资源错误，不一律重新登录掩盖问题                           |
| 已执行业务中途过期                   | 保存原 requestId/实例关联；恢复认证后先查询原结果，不直接重跑写用例 |

Cookie expiry 只用于提前提示，实际接口检查才是准入依据。logout、注销、会话撤销等用例可能令同一服务端会话的所有副本失效，不能因用了不同 Context 就认为互不影响；这些用例使用独立登录会话，或串行放在最后并明确需要重新初始化。

## 6. 测试分层与生产资源边界

| 测试组         | 覆盖内容                                                                               | 资源及运行要求                                                           |
| -------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 只读冒烟       | 版本、登录邮箱、管理员页面、主机/项目/会话列表、历史分页、已有文件只读预览、浏览器错误 | 默认组；只检查指定资源，报告不保存真实聊天正文                           |
| 隔离业务       | 创建/停止测试会话、上传、项目 CRUD、原请求查询、精确取消                               | 专用测试 Agent、独立项目和临时目录；按运行编号标记                       |
| 恢复与多标签页 | 测试 Context 离线/重连、刷新、重复请求去重、历史尾部恢复、控制权接管                   | 故障只注入测试浏览器连接，不关闭生产 Worker 或全机网络                   |
| 管理变更       | 配置读取/替换、重启、绑定/撤销                                                         | 仅指定测试实例，串行；先记录原配置 revision 与备份，禁止操作真实用户实例 |
| 模型任务       | 明确新意图、生成输出、审批与任务恢复                                                   | 显式启用，限定模型请求数、时长和费用；默认不执行                         |
| 权限与登录边界 | 未登录、游客、普通用户、失效会话、注销                                                 | 独立身份；必要的破坏会话用例最后执行，不沿用管理员状态                   |

默认 `workers=1`；只读组验证隔离后才考虑有限并行。管理员共享身份只解决认证复用，不提供业务资源隔离。配置、项目与授权写入即使作用于不同页面也可能相互干扰。

本机当前用户 Agent 曾发现代理失败及历史预算超限，不能直接作为健康的全功能测试夹具。先修复或建立独立配置/dataDir/host 身份的测试 Agent，避免测试触发已有用户会话或修改其历史。

## 7. 幂等、清理与未知结果

每轮生成唯一 runId；测试日志记录本轮创建的资源 ID、原 requestId、实例、必要控制代际和预期结果，不记录凭据及正文。操作测试可以复用原请求验证去重，但不能为了通过测试重置业务身份或删除去重证据。

- 副作用用例默认禁用 Playwright 整体自动 retry；断流后查询原请求结果，必要时在协议允许范围内重发同一原意图，不自动生成新 requestId。
- `RESULT_UNKNOWN` 终止相关流程并列入待核对清单；不能宣称操作失败，也不自动重发创建、模型任务或删除。
- 清理只根据本轮资源清单和归属标记执行，不按名称前缀遍历删除所有相似资源。仍有活动任务/未决结果的资源保留并报告。
- 配置恢复使用 revision 比较；发现并发人工修改时停止自动覆盖，报告差异范围。重启测试只允许专用测试实例且确认空闲。
- 初始化、前置条件失败和清理失败单独报告；不能为了让总结果变绿而跳过必需用例或隐藏残留状态。

## 8. 拟实现文件与命令

自动化浏览器适合使用现有 TypeScript/Playwright 工具链；它驱动真实网页和 C++ Agent，不把 Agent 业务逻辑迁移为 TypeScript。

建议文件：`scripts/online-auth.ts`（headless 初始化/认证快照）、`tests/online/fixtures.ts`（准入与资源隔离）、`tests/online/*.spec.ts`、独立 Playwright 配置，以及忽略目录中的运行配置。具体名称在实现批次固定。

以下命令是拟议接口，当前不可执行：

```bash
npm run test:online:auth -- --config .local/online-tests/config.json
npm run test:online -- --config .local/online-tests/config.json --group smoke
npm run test:online -- --config .local/online-tests/config.json --group isolated
```

初始化命令在需要时通过 stdin 等待验证码，不提供 `--otp CODE` 参数。模型组、重启组等由显式配置选择，不随 smoke 默认启动。

拟议运行配置不包含验证码或 Cookie：

```json
{
  "baseURL": "https://r.xlogic.cc",
  "expectedAdminEmail": "huangjielg@gmail.com",
  "authStateFile": ".local/online-tests/auth/admin.json",
  "workers": 1,
  "allowModelTasks": false,
  "allowRestart": false,
  "testResources": {
    "hostId": "填写专用测试主机ID",
    "projectId": "填写专用测试项目ID"
  }
}
```

实现必须拒绝占位 ID 和未知配置字段；写用例缺少目标资源时直接拒绝运行。只能在指定 HTTPS origin 执行业务操作，认证重定向域按独立允许列表处理；不接受任意测试参数让管理员浏览器访问不受信任目标。

## 9. 实施批次和验收

1. **认证初始化与过期检测：** headless 浏览器、等待验证码、两层身份验证、认证字段白名单、私有原子存储。先用本地可控登录夹具测试错误码、超时、重发、跨域导航和秘密不落日志；线上首次人工验证码为独立验收。
2. **只读线上冒烟：** 页面/API 断言、版本身份、预检错误分类、脱敏报告；验证重开浏览器仍可登录且无旧业务待办。
3. **专用 Agent 业务组：** 测试资源归属、原请求恢复、清理与残留清单；先本地回归，再指定线上测试实例。
4. **恢复与管理组：** 多标签页、断线、失效登录、配置冲突与重启；分别给出副作用范围和实际执行证据。
5. **可选调度：** 先在本远程机器人工触发，稳定后考虑定时或受控 runner。普通 GitHub Actions 的本地回归不依赖生产邮箱验证码；不能将短期管理员 Cookie 上传公开制品供云端 runner 长期复用。

每批代码及文档一起提交，本地检查通过后再推送。线上测试不能替代精确发布源码的六项必需 CI；CI 通过也不能代替真实 Access 邮箱登录验收。

报告包括：时间、目标、实际部署版本/commit、认证检查结果、执行测试组、测试资源、逐项状态、原请求恢复结果及残留资源。验证码输入阶段关闭 trace/视频/截图；业务阶段采集诊断时过滤 Cookie/Authorization/Access token、请求正文和敏感配置。原始诊断默认私有，公开文档仅保留脱敏证据。

## 10. 外部依据与待验证项

- [Playwright Authentication](https://playwright.dev/docs/auth)：复用 storageState、测试状态隔离以及敏感认证文件保护。其支持持久化存储不代表本项目应复制所有业务存储。

以下步骤用于本轮历史优化验收；不把第 11 节既有登录成功当作当前凭证仍有效或新源码业务测试通过。先记录网页与 Agent 各自实际源码/版本；线上旧网页的结果不能证明尚未发布的前端修改。

2. 使用指定隔离测试实例及已记录的原历史引用，检查普通文本、命令输出、文件变更的列表摘要、展开详情和 Unicode 首/中/尾页，核对实际正文摘要，不把敏感正文写入公开报告。
