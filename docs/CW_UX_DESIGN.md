# CW 界面美化与工作台功能设计

状态：**待评审、待实施**。日期：2026-11-02。源码调研基线：`1da85c0`。本次仅编写设计文档，不修改网页、协议、Agent 或部署状态。下文尺寸、性能预算和工期均为建议目标，不是已验证结果。

## 1. 目标与推荐范围

将 CW 从以对话为中心、通过弹窗访问辅助功能的界面，逐步升级为轻量远程开发工作台：对话仍是主区域，文件、命令输出、审批和连接状态可以在同一屏协作。

推荐先交付完全位于网页层的 P0–P3：统一视觉、优化对话格式、常驻文件浏览器、命令输出面板及操作反馈。真正可输入命令的交互式 Terminal 放在 P4，单独扩展最小必要的服务端能力。文件浏览器是对已有功能的升级；命令输出面板不能作为交互式终端已经完成的验收依据。

约束：

- 主要改动位于 `apps/web/src/`，可增加网页依赖和测试；P0–P3 不新增 Agent、Relay 或协议能力。
- 保留现有认证、项目隔离、一写多读、审批、上传恢复、可靠投递与历史恢复语义。界面状态不是授权依据。
- 不把界面重构与传输协议重写混在一起，不把后台管理页面改造成 IDE。
- 保留中英文、窄屏、键盘操作和旧功能入口；新增能力不可用时说明原因。

## 3. 信息架构与布局

### 3.1 桌面工作台

建议布局如下（设计线框，非产品截图）：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ CW  主机 / 项目 / 会话    连接状态 · 可写/只读      搜索  外观  菜单   │
├──────────────────┬───────────────────────────┬───────────────────────┤
│ 会话 | 文件      │ 对话标题 · 模型           │ 文件预览 / 变更       │
│ 搜索当前列表     │                           │ 路径、复制、下载      │
│ 目录树或会话列表 │ 消息、计划、工具摘要      │ 内容 / Diff           │
│                  │                           │                       │
│                  │ 待审批卡片（存在时）      │ 可关闭                │
│                  │ 输入框、附件、发送/停止   │                       │
├──────────────────┴───────────────────────────┴───────────────────────┤
│ 命令输出 | Terminal（支持时）       查找  清屏  最大化  收起          │
│ 当前命令、工作目录、状态、输出                                       │
└──────────────────────────────────────────────────────────────────────┘
```

- 顶栏约 52–56 px；主机/项目切换始终显示完整上下文入口，长名称省略但可展开查看。
- 左栏默认 256 px，允许在 220–360 px 拖动；会话与文件使用页签，避免同时塞入两套长列表。
- 对话正文居中，建议最大宽度 840 px；预览开启时允许正文缩窄，但不得压到 480 px 以下。空间不足时预览覆盖右侧而不是强制四处滚动。
- 右侧预览建议 360–560 px，仅在用户打开文件时出现。底部面板默认收起，展开约 240 px，可调高和最大化。
- 桌面三栏建议从 1280 px 开始；900–1279 px 默认两栏，预览使用抽屉；小于 900 px 默认单栏。实际判断兼顾缩放后的可用宽度。
- 分隔条可拖动也可键盘调整，双击恢复默认；宽度、高度、面板开关作为本机偏好保存，不保存远端控制权。

### 3.2 手机与窄屏

- 顶栏保留项目、状态及菜单；底部以“对话 / 文件 / 输出”切换主内容，不同时显示多栏。
- 输入区适配软键盘、动态视口和安全区域；输入框增长上限约为可用高度的 35%，其后内部滚动。
- 文件预览和 Terminal 最大化为独立全屏区域，提供明确的返回键。抽屉关闭后恢复原焦点和滚动位置。
- 宽表格、代码和 Diff 只在自身区域横向滚动，页面整体不得横向溢出。
- 移动端交互热区建议至少 44 × 44 px；审批到达时显示醒目提示，但不自动切屏打断正在阅读的文件。

## 4. 配色、字体与组件视觉

采用低饱和中性色作为主体，蓝色表示主要操作，状态色只用于对应语义。避免每一块内容都使用高对比边框或大面积彩色背景。

| 语义变量（拟新增） | 深色建议 | 浅色建议 | 用途 |
| --- | --- | --- | --- |
| `--cw-bg` | `#11151C` | `#F5F7FB` | 页面底色 |
| `--cw-surface` | `#191F2A` | `#FFFFFF` | 面板、输入框 |
| `--cw-surface-hover` | `#242D3B` | `#EAF0F8` | 悬停、次级区域 |
| `--cw-text` | `#E8EDF5` | `#182230` | 正文 |
| `--cw-text-muted` | `#A6B2C5` | `#526174` | 次级信息 |
| `--cw-border` | `#354155` | `#CBD5E1` | 分隔线、控件边框 |
| `--cw-accent` | `#8AB4FF` | `#245BCC` | 链接、选中、焦点 |
| `--cw-success` | `#6ED6AD` | `#16734A` | 完成、已连接 |
| `--cw-warning` | `#F5CC76` | `#8A5700` | 待审批、结果待确认 |
| `--cw-danger` | `#FF9AA8` | `#B4233C` | 失败、危险操作 |

- 主按钮单独定义背景/前景组合：深色可用 `#8AB4FF` + `#11151C`，浅色可用 `#245BCC` + 白色。不能把同一 accent 值无条件当成所有按钮的背景和文字。
- 上述配色需对最终背景组合实测；验收目标为普通正文对比度至少 4.5:1、重要图标/控件边界至少 3:1。状态同时有文字或图标，不只依赖红绿颜色。
- 正文字号建议 15–16 px，中文行高 1.7，界面标签 13–14 px；标题控制在 18–22 px。使用系统中文字体回退，避免加载外部字体成为首屏依赖。
- 代码字号 13–14 px、行高 1.55，使用等宽字体；支持标准/紧凑密度，但紧凑模式不缩小触屏热区。
- 间距以 4/8/12/16/24/32 px 为阶梯；控件圆角 8 px、卡片 12 px，阴影主要用于浮层。
- 图标保持统一线宽，常用操作使用图标加文字；仅图标按钮提供可访问名称和提示。发送为主操作，停止与结束会话在位置和文案上明确区分。
- 动画限于短淡入和尺寸过渡，遵循减少动态效果偏好；流式文本不做逐字闪烁动画。
- 新变量和布局样式限定在 `.cw-workbench` 范围，避免全局 `button`、`main` 等改动意外影响管理页面。管理界面迁移主题需独立回归。

## 5. 对话内容美化与格式化

### 5.1 消息与 Markdown

- 用户消息采用轻背景容器，助手消息采用文档式正文；角色、时间和操作放入轻量头部。用户原始文本保留换行，不擅自按 Markdown 解释。
- 助手 Markdown 统一标题间距、段落、列表、引用、分隔线和表格样式。表格提供局部横向滚动；长链接和路径可断行。
- 代码块增加语言标签、复制、折行开关、展开/收起；长代码可选行号，复制始终取得原文而非行号或高亮标记。
- 语法高亮作为按需加载能力，首批只加载常用语言，未知语言以纯文本显示。依赖选型在实施时验证维护情况、许可和包体积，本方案不锁定新增库版本。
- Diff 保留 `+/-`、文件路径和上下文标记；默认统一视图，宽屏才提供并排视图，长 Diff 按文件折叠。不根据颜色推断可直接应用补丁。
- 文件链接打开侧栏预览；支持“在文件树中定位”“复制相对路径”“新窗口预览”。找不到项目归属或越界时显示说明，不尝试访问任意主机路径。
- 增加高级 Markdown 支持，涵盖公式、Mermaid、脚注、提示块和目录，按 5.4–5.5 节分批落地。继续限制 URL 协议、原始 HTML 和图片加载，格式化不引入任意 HTML 或脚本执行。

### 5.2 工具、计划与审批

- 每轮对话按“用户请求 → 计划/进度 → 工具摘要 → 回复”组织；一轮多个工具可折叠为组，失败和待审批保留显式标识。
- 工具摘要显示可用的命令、工作目录、运行/完成/失败状态；耗时、退出码仅在事件提供时显示，缺失字段显示未知，不从文本猜测成功。
- 输出正文仍按 `contentSeq/revision` 按需读取；展开前不预取全部输出，不改变事件顺序、引用回收或 ACK 逻辑。
- 计划使用步骤列表和状态标记；旧事件缺少结构时回退到原文。
- 审批卡片固定在输入区附近，展示命令/文件 Diff、目标项目、权限范围、原因以及待确认数量；允许和拒绝同屏可见，不能折叠到只有颜色提示。

### 5.3 流式显示与阅读位置

- 已完成消息稳定复用，只更新正在流式生成的消息；可把频繁 UI 更新合并到约 50–100 ms，事件接收和确认不依赖渲染节奏。
- 未闭合代码围栏先显示可读原文，完成后再高亮；异步高亮结果校验消息和 revision，避免旧结果覆盖新内容。
- 阅读历史时不强制回底部，显示“有新内容 / 回到最新”；工具展开、图片尺寸变化和加载更早历史须保持阅读锚点。
- 长会话先采用组件记忆化、分块和按需读取；只有测量证明仍有瓶颈才引入虚拟列表，并单独验证选择复制、查找、焦点和滚动锚点。

### 5.4 高级 Markdown 功能规格

高级格式同时覆盖助手回复、文件侧栏预览和独立 Markdown 预览页，使用同一套语法配置与主题。用户消息默认保持原文，可主动切换“格式化预览”；工具日志默认纯文本，避免把命令输出误判成文档。基础 Markdown/GFM 继续兼容，无法识别的扩展保留源码。

| 能力 | 拟支持语法与呈现 | 交互和边界 | 实施阶段 |
| --- | --- | --- | --- |
| 数学公式 | 行内 `$...$`、独占行 `$$...$$` 数学块，以及标记为 `math` 的代码围栏；覆盖分式、矩阵、多行对齐和常见符号 | 长公式局部滚动，支持复制公式源码；解析失败显示原文和局部提示，不隐藏整条消息 | P1b |
| Mermaid 图表 | 标记为 `mermaid` 的代码围栏；首批流程图、时序图、状态图、类图和 ER 图 | 图形/源码切换、缩放、适应宽度、全屏；提供源码复制与 PNG 导出，未支持语法回退代码块 | P1b |
| 脚注 | `[^id]` 引用和对应定义 | 文末脚注列表、跳转和返回；同条消息内解析，不跨消息拼接引用 | P1a |
| 提示块 | 引用块首行 `[!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]`、`[!CAUTION]` | 图标、标题和柔和背景；含义不只靠颜色；警告与注意类默认展开 | P1a |
| 标题锚点和目录 | 依据 Markdown 标题树自动生成；建议至少 3 个标题时显示目录入口 | 中文标题与重复标题有稳定唯一锚点；对话目录限当前消息，文件目录覆盖当前文件，不额外占用常驻侧栏 | P1a |
| 可折叠长内容 | 长代码/表格提供组件级展开；显式折叠块采用约定扩展 `:::details 标题`，以单独一行 `:::` 结束 | 首版不支持嵌套折叠指令；有键盘操作及展开状态，展开不发起业务操作；不靠开放原始 `<details>` HTML 实现 | P2 |
| 表格增强 | GFM 对齐、表头样式、局部滚动、展开查看和复制为 TSV | 保持原行序，不默认排序、不执行单元格内容；复制失败可手动选择 | P1a |
| 任务列表与删除线 | 沿用 GFM 的 `- [ ]`、`- [x]` 和 `~~文本~~` | 任务复选框仅展示原文状态，不通过点击修改消息或远端文件 | P1a |
| 图片与图注 | Markdown 图片保留替代文字，标题可作为图注；项目内允许格式按文件通道预览 | 外部图片默认显示占位与域名，用户主动加载后才请求；限制尺寸，不自动加载任意 SVG/HTML | P2 |

解析约定：

- 以 Markdown 语法树识别扩展，不用正则替换整段 HTML。代码围栏和行内代码中的 `$`、脚注或指令均保持字面文本。
- 行内公式要求同一行有成对且紧邻非空内容的分隔符；独立货币符号如 `$100` 不触发公式。支持 `\$` 转义；遇到货币与公式歧义，提供“查看原文”，不能承诺无歧义自动识别。
- 脚注、标题和图表 DOM ID 加入文档/消息作用域，重复渲染和不同消息的相同标题互不冲突。保留项目文件链接识别；`#标题` 导航到当前文档内锚点，不覆盖 CW 用于路由的 URL hash。
- 提示块不改写正文内容或提升权限；从未闭合的指令块回退为原文。未知扩展不报整页错误。
- 格式化是显示层能力，数据库和导出 Markdown 保留原始文本；复制“原文”和复制表格/公式等局部内容的入口明确区分。图表导出只针对已完成且成功渲染的内容。

### 5.5 高级 Markdown 实现、安全与流式策略

**渲染管线。** 在现有 `react-markdown` 与 `remark-gfm` 基础上提取共享 `MarkdownRenderer`，先解析语法树，再生成经过约束的 React 组件；公式、图表、代码高亮通过独立适配器按需加载。拟新增 `markdown/` 目录管理语法配置、主题、锚点及扩展组件，不在三个预览入口各自复制插件链。具体数学和图表引擎在实施时验证维护状况、许可证、CSP 兼容性、中文字体和资源开销，不在本设计锁定版本。

**不可信内容边界。** 不启用任意原始 HTML、MDX、内嵌 JavaScript、iframe 或远端插件。数学引擎禁用可信 HTML/外部资源扩展并限制宏展开；图表禁用交互回调、脚本、外部资源和内容自带的安全配置覆盖。生成的 SVG/HTML 仍须按明确允许列表清理，过滤事件属性、危险 URL、外部引用及 `foreignObject` 等非必要节点；复杂图表必要时放入不具备同源权限的沙箱容器。不能因为是渲染库输出就直接信任其字符串。外链保留现有协议限制和新窗口隔离规则。

**流式显示。** 正在输入的公式、图表和折叠块先展示源码占位，语法闭合且内容稳定后渲染；复杂图表默认等待该条回复完成，用户可主动预览当前完整块。逐块缓存，建议键包含作用域、源码摘要、主题及渲染器版本；只更新发生变化的块。异步结果绑定消息 revision，过期结果丢弃；占位预留合理高度，渲染后保持阅读锚点。历史分页只补充语法上下文已知的内容，片段缺少开头时按原文展示，不把孤立分片猜成完整文档。

**资源预算与失败回退。** 初始建议单个图表源码最多 32 KiB、最多 300 个节点、单次渲染预算 2 秒；公式块源码最多 16 KiB，并配置宏展开上限。数值需基准验证后调整。限时必须通过可终止的 Worker 或隔离渲染上下文实现；主线程计时器不能中断同步解析，无法可靠限制时直接回退源码。长文按块懒渲染，缓存有字节上限，超限、依赖加载失败和语法错误仅影响当前块；均保留复制/查看源码入口。公式、图表、字体和高亮资源随网站构建提供，不依赖运行时公共 CDN。

**可访问性。** 公式提供适合辅助技术的语义表示和源码入口；图表提供标题/说明及可聚焦的源码切换，不能只用颜色表达关系。缩放按钮、目录、脚注和折叠组件均支持键盘；弹出全屏后焦点受控，关闭恢复焦点。深浅色主题下图中文字、连线和公式均独立检查可读性。

## 6. 文件浏览器

### 6.1 第一版工作流：纯网页升级

1. 用户切换到左栏“文件”，只加载当前项目根目录。
2. 展开目录时懒加载该目录，沿用 `/hosts/{host}/files` 的 `list`、`path`、`after` 和 `next`，每个目录独立分页、加载和失败状态。
3. 点击文件在右侧预览；文本提供行号和本文件查找，Markdown 可切换源码/渲染视图。复用现有下载能力读取数据，保持独立预览链接可用。
4. 点击“引用到对话”插入明确的项目相对路径到草稿，由用户确认发送；默认不把整个文件内容塞入消息，也不自动发起任务。
5. 上传作为文件栏中的显式操作，进度放在传输区；收起文件栏不丢失上传记录。覆盖确认、暂停/恢复和未知结果恢复继续使用现有逻辑。

### 6.2 交互细节与边界

| 能力 | 第一版方案 | 限制与后续扩展 |
| --- | --- | --- |
| 目录树 | 文件类型图标、懒展开、面包屑、刷新、复制路径 | 不递归扫描整个项目；树键盘导航覆盖方向键、Enter 和 Home/End |
| 搜索/排序 | 过滤当前已加载目录项，名称/类型/大小排序 | 文案明确“筛选已加载项”；未读分页存在时不能宣称全目录排序或全项目搜索 |
| 预览 | 文本和 Markdown 共用组件，复用已有安全下载通道 | 建议 1 MiB 为内联预览阈值，先检查已知大小；无大小时读取端设字节上限并中止，不先下载完整大文件再检查 |
| 图片/二进制 | 二进制默认下载；图片预览后续只开放明确允许的格式 | 不直接内联任意 SVG/HTML；生成的 Blob URL 及时释放 |
| 上传 | 保留单文件流程，可增加拖放选择和进度展示 | 服务器 `maxSize/writable` 为准；批量、文件夹上传后续再评估 |
| 缓存 | 内存缓存已展开目录和少量预览，按 host/project/path 隔离 | 手动刷新、上传成功后失效对应目录；不引入后台轮询，不把缓存标成实时文件系统 |
| 文件管理 | 本期不增加删除、重命名、新建、在线编辑和保存 | 现有上传覆盖不等于具备并发安全编辑协议；这些能力需另行设计权限、版本冲突和恢复 |

切换主机/项目时取消读取并清空当前视图，迟到响应校验上下文；上传仍按原 host/project 归属显示，不能随页面切换改目标。文件权限遵循文件接口自身的服务端判定，不能仅凭会话“可写”推断可上传，也不能把“只读观察会话”误认为全账号没有文件权限。

## 7. Terminal 功能：分阶段完成

### 7.1 P3：命令输出面板（网页即可实现）

新增底部“命令输出”页签，复用 `item/started`、`item/completed` 和 `item/commandExecution/outputDelta`，以会话/轮次/工具项分组。对话与输出面板共享事件和正文缓存，不建立第二套历史订阅或 ACK 链。

- 显示命令、工作目录、退出状态、可获得的时间信息；提供查找、复制、下载已加载输出、自动跟随、暂停跟随和清空当前视图。
- 输出格式先使用纯文本与有限 ANSI 颜色解析；禁用控制序列触发剪贴板、浏览器跳转或任意 DOM 注入。
- “清屏”只影响显示，不删除远端历史；导出注明是否完整，未读完时不得标成完整日志。
- 输入命令区域不出现。可以提供“请助手处理此命令”入口，把文字放回对话草稿，清楚表明这是待发送请求，不能宣传为直接 Shell 执行。
- 停止操作若提供，只能明确标为“停止当前助手任务”，复用现有中断流程；不能把它标成终端 Ctrl+C 或单进程终止。

### 7.2 P4：交互式 Terminal（需要最小后端扩展）

目标：用户在网页直接使用远端项目终端，能够键入命令、调整窗口尺寸、发送 Ctrl+C、查看输出并显式关闭进程。浏览器渲染器只处理显示和输入；PTY/ConPTY、进程管理和授权必须由 Agent/Relay 提供。不能只安装前端终端组件就宣称具备该能力。

建议以独立设计评审后的最小增量实现，以下接口名均为**拟议语义**，不是现有可调用 API：

| 层次 | 必要改动 | 责任 |
| --- | --- | --- |
| `apps/web/src/` | `terminal-panel`、终端渲染适配器、连接状态与输入队列 | 动态加载、尺寸适配、只读提示、粘贴确认、关闭确认 |
| `packages/protocol/` | 能力声明；`terminal.open/input/resize/close`；输出与退出事件 | 终端 ID、runtime 代次、输入/输出序号、字节配额及校验；同步原生验证规则 |
| `apps/relay/src/` | Terminal 路由和授权/连接绑定 | 校验账号、host、project、终端归属及写权限；限制流量，不开放任意 RPC 转发 |
| `native/` | 项目终端进程、PTY 生命周期、进程组回收与资源上限 | 校验启动目录、Shell 参数、系统权限和隔离；产生输出/退出状态，执行取消 |

授权与运行规则：

- 默认禁用，Agent 显式声明支持后显示入口；旧 Agent 正常使用文件与对话，只显示交互式终端不可用原因。
- 终端默认绑定账号、项目和控制连接，首版不共享可写终端。输入需要服务端认可的项目写权限；只读观察端无输入通道。
- 首版采取保守互斥：交互终端存活期间占用项目执行资格，拒绝并行助手写任务；运行中的助手任务也阻止开启可写终端。跨页面切换不能绕过占用，后续若做并行需另行设计。
- **仅设置 cwd 不能隔离 Shell**，也不能继承“Codex 沙箱”这一假设。必须有 Agent 侧可验证的进程隔离和资源策略，禁止自动提升权限或静默扩大到主机文件系统；做不到的目标平台不启用该能力。
- Terminal 的启动授权单独明确展示范围，既有模型自动审批选项不等于授权任意交互 Shell。参数数组启动固定允许的 Shell，不把网页输入拼入启动命令。

可靠性与资源规则：

- 创建、关闭使用可靠操作身份和结果查询；输入使用 terminal/runtime/序号去重。同一输入不能因重连被执行两次，也不能把结果未知的命令换新身份重放。
- PTY 写入与持久记录无法天然形成原子事务；Agent 崩溃落在写入边界时须报告输入结果未知并关闭该 runtime，不承诺任意 Shell 命令恰好执行一次，不自动续传旧按键。
- 输出按序号和字节窗口流控，使用有界内存环形缓冲；落后超出保留范围时明确提示缺口。不要把每个字符变成长期数据库事件，也不能挤占审批/中断优先通道。
- 断线立即禁用输入；同 runtime 且仍获授权才允许显式恢复。建议首版断线宽限 60 秒后终止进程组，具体超时和终端数上限需实现时配置并测试。
- 权限撤销、项目移除、Agent 退出必须终止相关终端及子进程。收起面板不等于结束；关闭页签明确区分隐藏和终止。
- 多行粘贴显示确认；渲染器不响应远端剪贴板写入和自动链接打开。键盘焦点进入终端时才转发输入，选择文本时保留复制行为。
- 首版不持久化输入记录或完整终端日志到浏览器；审计记录必要的创建/关闭与授权元数据。输出导出由用户主动触发。

平台顺序建议先完成 Linux PTY 及隔离验证，再评估 Windows ConPTY；未验证平台通过能力声明禁用。原生能力发布仍遵循仓库 CI、制品身份验证和部署脚本要求，不能因为功能主要显示在网页就跳过这些检查。

## 9. 网页实现组织与数据边界

建议按职责拆分，以下目录均为拟新增，避免一次性改写整个 `main.tsx`：

```text
apps/web/src/
  workbench/     外壳、侧栏、底部面板、布局偏好
  ui/            按钮、页签、提示、空态、抽屉、分隔条
  conversation/  消息、Markdown、代码、工具组、计划（逐步提取）
  explorer/      文件树、预览容器、目录缓存、传输视图
  terminal/      命令输出；后续交互终端适配器
  styles/        CW 变量、布局、内容样式
```

- `main.tsx` 第一阶段只装配外壳和现有回调；`operations.ts`、`delivery.ts`、`history-subscription.ts`、`uploads.ts` 等继续负责业务状态。
- 文件预览和对话共享 Markdown/代码呈现组件，但不同上下文保留各自 URL/文件访问规则；共享外观不等于放宽访问权限。
- 主题、密度、布局等小型非敏感偏好使用带版本的本地配置；草稿、历史和上传记录沿用现有存储与预算，不再建立第二套 IndexedDB 历史库。
- 控制权、任务完成、文件权限和终端状态均来自服务器；本机偏好或离线缓存不能恢复可写资格。
- 异步读取绑定 host/project/session/revision；组件卸载和上下文切换后取消或丢弃旧响应。切页签不得意外销毁正在运行的上传状态机。
- 新高亮、公式、图表和终端依赖动态加载；不引入全量 IDE 编辑器作为文件查看器。先测量，再决定是否需要额外状态管理或虚拟列表库。

## 11. 验收与测试方案

### 11.1 功能和视觉

- 截图矩阵：1440 × 900、1024 × 768、390 × 844；深/浅主题，中英文，空态、流式回答、代码/表格、长路径、审批、文件预览、命令输出、只读和离线状态。
- 补测 320 px 窄屏、浏览器 200% 缩放、软键盘弹出、触摸操作；正文无截断，页面无横向溢出，主要动作可见。
- 键盘可完成切换面板、浏览目录、预览、复制、审批与返回；焦点可见，弹窗焦点受控，关闭后回到触发位置；状态播报不逐字朗读流式正文。
- 文件名和消息包含超长文本、中文、恶意链接、HTML、控制字符时保持安全呈现；检查路径越界、符号链接逃逸和未经授权项目仍由服务端拒绝。
- 验证同项目一写多读、不同项目独立、写权限移交、拒绝后草稿保留、未知结果查询、断网恢复及审批优先级不退化。
- 高级 Markdown 使用固定语料验证助手消息、侧栏预览和独立预览一致：分式/矩阵/多行公式、五类 Mermaid、脚注往返、重复中文标题、提示块、长表格、折叠块和图片占位；检查源码复制与导出无损。
- 覆盖未闭合围栏/公式、逐字符流式更新、历史分片、主题切换及旧 revision 晚到；验证货币符号和代码字面量不被误解析，异步渲染不夺取焦点或滚动位置。
- 安全语料包含 HTML/脚本、危险链接、图表回调/外部资源、SVG 注入、公式宏展开和超大图表；断言没有非用户触发的外部请求、脚本执行或主线程长时间阻塞，失败时仍可读原文。

### 11.2 性能目标

在固定机器、浏览器和测试数据上保存改动前后指标；建议数据包含 1,000 条历史事件、100 KiB 代码块、连续工具输出、目录 1,000 项分页。下列仅为初始预算，评审时据基线调整：

- 已缓存面板切换的 p95 小于 150 ms；输入交互目标小于 100 ms；记录长任务和内存变化，不用网络时间代替前端耗时。
- 懒加载目录和输出；面板收起不持续读取正文，空闲页面无新增轮询，命令面板不新增重复历史请求。
- P0–P3 主入口 gzip 增量建议控制在 50 KiB 内，较大的可选依赖进入异步包；以构建报告核对，不在文档中预先宣称达标。
- 分别记录高级 Markdown 异步包和字体体积、首次/缓存渲染耗时；追加含 20 个公式块与 10 个图表的长文基准，验证只渲染可见或用户展开内容，超出 5.5 节预算可终止并回退。
- 多次切换项目、打开/关闭预览后内存回到稳定区间；缓存沿用或纳入现有预算，AbortController、监听器和 Blob URL 均释放。

### 11.3 自动化与发布门禁

- 网页实现后运行 `npm run typecheck`、`npm run lint`、`npm run build:web`，补充必要的消息呈现、目录状态、上下文切换和偏好迁移单测。
- 在现有 `npm run test:ui`、`npm run test:e2e` 和 `npm run test:e2e:d1` 上补充布局/权限/审批场景；文件改动复用 `npm run test:uploads:web`，可靠操作改动复用 `npm run test:operations:web`。
- P4 额外测试重复输入、崩溃写入边界、输出截断、背压、断线到期、权限撤销、项目切换、恶意控制序列和进程组清理；真实 Shell 测试放在隔离临时项目中。
- 后续功能落地同步更新 `USER_GUIDE.md`、`CHANGELOG.md` 以及受影响的需求、架构和开发文档；测试结果写入测试报告，实际部署后才更新部署记录。
- 所需 Actions 作业全部通过且提交身份一致后才进入发布流程；本设计不包含任何部署授权。

## 12. 评审建议与本次交付边界

建议确认“P0–P3 网页优先，P4 交互终端独立实施”的顺序。主要取舍是：先改善每天使用的阅读、导航与反馈，再承担 Shell 生命周期和隔离带来的跨端复杂度。全项目搜索、在线编辑、完整 Git 管理、协作共享终端不纳入第一版。

最初交付为设计文档。后续用户已授权新建 worktree 实施，并明确纳入 P4a 的 Agent、协议和 Relay 改动；当前实现范围、限制与本机验证见 [CW 工作台实施记录](CW_WORKBENCH.md)。上文是完整设计目标，并非所有建议均已实现，也不表示已经发布。P4b Windows 隔离仍需独立平台验证。
