## 实施优化

1. D1 事务每次 CAS 尝试内缓存重复 get，包括不存在的 key，并返回独立对象。邮箱授权验证、host 校验和 authHost 返回值会读取相同 host，lastSeen 更新也会再次读取 grant；现在每个 key 每次尝试只访问一次。修改对象不会隐式保存，put / delete 后读取仍优先返回缓冲结果。缓存不跨事务，冲突重试全部失效。
2. UPSERT 只有 JSON 文本不同才更新 relay_state。同一凭据 lastSeen 更新时，其 expires 不变，相同 due 索引跳过重写；同值状态也跳过物理更新。scope 修订号与 token 仍照常提交，保持并发 fencing。
3. 增加 `scripts/d1-usage.py`，通过 Wrangler info / insights / execute 只读记录指标、聚合与计划。显式指定数据库，不输出状态正文，不包含写 SQL。

未改变授权缓存时长、所有权协议、活动会话归属、清理额度或生产 schema。未清理历史数据，也未重启活动 Agent。

## 验证与边界

真实 SQLite 测试验证并发重复读取、缺失 key、对象修改隔离、写后读、删除后读、跨事务授权撤销及 scope 冲突后重新读取。相同的 auth 和 due 再次保存时，SQLite total_changes 从三行（scope、auth、due）降到一行（scope），此特定场景物理行变更减少 67%；并不代表线上总写入量下降 67%。
